# LightNote 공유 노트(OneDrive 동기화) — 설계

A PC(회사)와 B PC(집)에서 같은 노트를 보고 고친다. 동기화는 OneDrive가
파일 단위로 해 주고, 앱은 **켜둔 창이 묵은 내용을 덮어쓰는 것만** 막는다.

## 전제 (사용자 확정)

**혼자 쓴다. 자리를 옮겨가며 순차로 쓴다. 동시에 고칠 일이 없다.**

그래서 **잠금·충돌 병합·"양쪽 다 남기기" 3지선다는 전부 뺀다.** 이전 설계안에
있었으나 필요 없다 — 사무실 앱을 안 껐다는 이유로 집에서 읽기 전용이 되면
오히려 못 쓴다.

## 진짜 문제는 "동시 편집"이 아니라 "켜둔 앱의 묵은 메모리"

순차로 써도 매일 일어난다. 앱을 끄지 않고 자리를 옮기기 때문이다.

| 쓰는 방식 | 지금 상태 |
|---|---|
| 옮기기 전에 **앱을 끈다** | **문제 없음** — 고칠 것도 없다 |
| 앱을 **켜둔 채** 옮겼다가 돌아와 그 페이지를 고친다 | 창이 들고 있던 묵은 본문이 저장된다 |
| 업무 속성·참조를 쓴다 (앱을 켜뒀다면) | **페이지와 무관하게 파일 통째로** 묻힌다 |

마지막 줄이 제일 나쁘다. 아침에 회사에서 앱을 켜면 `work-objects.json`
**전체**가 메모리에 올라오고, 집에서 하루치를 고친 뒤 저녁에 회사 PC에서
업무 속성을 하나만 건드리면 아침 스냅샷이 통째로 쓰인다.

## Phase 0 조사 결과 (현재 코드 기준)

- **데이터 루트가 한 군데서 정해진다** — `ipc-handlers.js:34-36`
  `app.getPath('appData')/lightnote/lightnote-data`. 여기만 바꾸면 전부 따라온다.
- **페이지는 파일 하나씩이다** — `.../sections/<sec>/pages/<pageId>.json`.
  첨부(`attachments/<pageId>/`)·기록(`versions/<pageId>/`)도 페이지별.
  **동기화에 가장 유리한 구조이고 이미 그렇게 돼 있다.**
- **본문에는 캐시가 없다** — `note-storage.js`는 매번 디스크를 다시 읽는다.
  가만히 있는 창은 저장하지 않는다(`isDirtyRef` 게이트).
  자동저장은 고친 뒤 1초(`Editor.tsx:1128`).
- **사이드카 둘만 캐시를 들고 무효화하지 않는다** —
  `work-object-storage.js`·`reference-storage.js`의
  `let cache = null` → `if (cache) return cache` → `writeAll(map)`이 통째 쓰기.
- **파일 감시가 없다** — 열린 창은 저쪽 PC가 그 파일을 바꾼 걸 끝내 모른다.
- **쓸 수 있는 장치가 이미 있다**:
  - `lightnote:page-changed` 브로드캐스트 → `Editor.tsx:662`의 "다른 창에서
    저장됨" 배너. **감시기가 같은 이벤트만 쏘면 PC 간에도 그대로 동작한다.**
  - `lightnote:save-page` 핸들러가 **버전 스냅샷 때문에 이전 내용을 이미 읽는다.**
    저장 전 확인은 **추가 읽기 없이 비교 한 줄**이다.
  - `page-versions` 스냅샷 — 잘못 덮어도 되돌릴 수 있다.
- **API 키는 데이터 루트 밖이다** — `appData/lightnote/lightnote-settings.json`.
  폴더를 옮겨도 **따라가지 않는다.** 회사 PC의 AI-off 상태는 그대로.
- 창 위치·스티커 목록은 `userData/window-settings.json`(PC별)이라 안 따라간다.
  스티커가 가리키는 **노트 자체는** 공유된다.

---

## 고칠 것 4가지

### 1. 사이드카 캐시 걷어내기 ★

`work-object-storage.js`, `reference-storage.js`의 `cache`를 없앤다. 맵이 작고
(노트당 객체 하나) 쓰기도 드물어 매번 읽어도 체감되지 않는다.
쓰기도 **읽고-고치고-쓰기**로 바꾼다 — `{ pageId: ... }` 꼴이라 **키 단위 병합**이
그대로 먹는다.

**OneDrive와 무관하게 지금도 버그다.** 창을 여러 개 띄우면 같은 일이 난다.
공유를 안 하기로 해도 이건 고친다.

### 2. 창이 포커스를 받으면 디스크에서 다시 읽기 ★

자리에 앉는 순간 최신으로 맞춘다. `window` 포커스 시 열린 페이지의 파일
`updatedAt`을 보고,

- 디스크가 더 새롭고 **고치던 게 없으면** → 조용히 다시 읽는다
- 고치던 게 있으면 → **기존 `remotelyChanged` 배너**를 띄운다(이미 있는 장치)

편집기·스티커 메모·기록장 창 모두 같은 방식. 스티커는 이미 같은 배너 로직이
들어가 있다.

### 3. 저장 직전 확인 (보험)

렌더러가 페이지를 읽을 때 받은 `updatedAt`을 저장 요청에 같이 보낸다.
`lightnote:save-page`가 이미 읽어 둔 이전 내용과 비교해서 다르면
**덮어쓰지 않고** 돌려보낸다 → 창은 배너를 띄운다.

동시 편집이 없다는 전제이므로 **3지선다를 묻지 않는다.** "저쪽이 더 새롭다"는
뜻이므로 불러오기를 권하고, 그래도 내 것을 쓰겠다면 한 번 더 누르게 한다.
어느 쪽이든 스냅샷이 남아 되돌릴 수 있다.

### 4. OneDrive 때문에 필요한 것

- **폴더 지정 설정** — "공유 노트 폴더". 비우면 지금처럼 로컬.
  PC마다 OneDrive 경로가 다르므로 **PC별 설정**(`window-settings.json`).
- **폴더가 없거나 비어 있으면 평소처럼 켜지 않는다.** 빈 데이터 루트로 열리면
  "노트가 전부 사라졌다"로 보이고, 그 상태에서 적으면 유령 폴더에 쌓인다.
  경로를 보여주는 안내 화면 + [다시 시도] [로컬로 되돌리기].
- **충돌 사본 알림** — 동기화가 늦게 도착하면 OneDrive가
  `notebooks-DESKTOP-A.json` 같은 사본을 남기는데 **지금 앱은 그냥 무시한다**
  (날아간 줄도 모른다). 찾아서 배너로 알리고, 페이지 사본이면 열어 준다.
- **`versions/`는 로컬에 남긴다** — 저장할 때마다 쌓여 동기화 트래픽만 늘리고,
  되돌리기는 각 PC에서만 쓰면 된다. `pageVersions.init()`에 로컬 루트를 따로
  넘기면 된다(한 줄).
- **파일 감시** — 데이터 루트를 감시해 열린 페이지 파일이 바뀌면
  `lightnote:page-changed`를 쏜다. 2번(포커스 시 재읽기)만으로도 대부분
  덮이므로, 감시는 **있으면 좋은 쪽**이다.

### 옮기기 (마이그레이션)

폴더 고르기 → **복사**(이동 아님) → 개수·용량 대조 → 설정 바꾸고 재시작.
**원본은 지우지 않는다.** 사용자가 직접 확인한 뒤 지운다.

## 구현 결과 (2026-10-17, 1~3단계 완료)

1. **1단계 — 묵은 메모리 막기.** ✅ 캐시 제거, 포커스 재읽기, 저장 전 확인.
2. **2단계 — 폴더 지정 + 마이그레이션 + 안내 화면 + `versions/` 로컬 분리.** ✅
3. **3단계 — 충돌 사본 알림 + 파일 감시.** ✅
4. **4단계 — 2PC로 1주 실제 운영 후 판정.** ← 남음(사용자)

검증: `scripts/verify-sync-safety.mjs` 47/47. 실제 앱을 띄워, 테스트가 직접
파일을 고쳐 "저쪽 PC가 바꿨다"를 흉내낸다.

### 만들면서 바뀐 것

- **저장이 거부됐을 때 빠져나갈 길을 넣었다.** 처음엔 배너에 [불러오기]만
  뒀는데, 그러면 막다른 길이 된다 — 새로고침은 내가 적던 걸 버리고, 닫으면
  다음 자동저장이 또 거부돼 영영 저장을 못 한다. [저쪽 것 불러오기] +
  [내 것으로 저장](덮이는 쪽은 스냅샷으로 남음) 둘을 준다. 스티커도 같다.
- **메아리 억제를 시간이 아니라 내용으로 가린다.** 감시기가 제 저장을
  "저쪽이 바꿨다"로 오해하지 않게 하는데, 처음엔 "몇 초 안이면 내 것"으로
  쟀다. 윈도우 폴더 감시는 변경을 모아서 늦게 주기도 해서, 짧게 잡으면 제
  저장이 새어 나오고 길게 잡으면 그 직후 온 저쪽 변경을 놓친다. 지금은
  **우리가 쓴 시각 값 자체**를 기억해 두고 파일에 적힌 값과 맞춰 본다.
- **감시기가 폴더를 미리 만든다.** 데이터 폴더는 첫 저장 때 생기는데, 없다고
  그냥 돌아가면 새 프로필에서는 그 세션 내내 감시가 죽어 있었다.
- **두 번째 PC가 붙을 길을 뒤늦게 넣었다.** 처음엔 "빈 폴더로 복사"만 있어서,
  정작 두 PC가 목적인데 두 번째 PC는 붙을 방법이 없었다(그 폴더엔 이미 노트가
  있어 복사가 거절된다). [이미 쓰던 폴더에 연결]을 따로 뒀다.
- **영구 삭제의 딸림 자료 정리를 기다린다(await).** 예전엔 띄워만 놓고 바로
  돌아왔다. 사이드카가 맵을 메모리에 들고 있던 때라 사실상 즉시 끝나 가려져
  있던 경합인데, 파일을 다시 읽게 되면서 "지웠는데 아직 남아 있는" 창이 생겼다.

## Non-goals

- 실시간 동시 편집 — 안 한다. 전제가 아니다.
- 자동 본문 병합 — 안 한다. 글을 기계가 섞으면 조용히 망가진다.
- 잠금·동시 사용 차단 — 안 한다. 자리를 옮겨 쓰는 걸 막게 된다.
- 일부 노트북만 공유 — `notebooks.json`이 전역이라 저장소를 두 벌로 나눠야
  한다. 비용 대비 이득이 적어 **전체 공유**.
- 다른 사람과의 공유 — 본인 PC 두 대만 본다.

## 정한 것 (처음에 열어 뒀던 3가지)

1. 1~3단계를 한 번에 했다.
2. `versions/`(페이지 기록)는 **로컬에만** 둔다 — 옮길 때도 가져가지 않는다.
3. 저장이 거부되면 **"저쪽 것 불러오기"를 먼저** 보여 준다(저쪽이 더 새로운
   것이 맞으므로). 단, "내 것으로 저장"도 같이 둔다(위의 막다른 길 참고).

## 쓰기 시작할 때

1. 설정 → **공유 노트 폴더 → [폴더 고르기…]** 에서 OneDrive 안의 **빈 폴더**를
   고른다. 지금 노트를 그리로 복사하고 앱이 다시 뜬다. **원본은 안 지운다** —
   며칠 써 보고 직접 지우면 된다.
2. 다른 PC에서는 **[이미 쓰던 폴더에 연결…]** 으로 같은 폴더를 고른다.
   복사하지 않고 가리키기만 한다(그 폴더엔 이미 노트가 있으므로 복사는
   일부러 거절한다 — 덮어쓰기 사고를 막으려고).
3. OneDrive에서 그 폴더에 **"항상 이 디바이스에 유지"**를 켠다.

## OneDrive 쪽 설정 (사용자)

- 해당 폴더에 **"항상 이 디바이스에 유지"** 켜기. 안 켜면 클라우드 전용
  자리표시자가 되어 오프라인에서 읽기가 실패한다.
- 자리를 옮기기 전에 **동기화가 끝난 것을 확인**하면 가장 안전하다.
  1~3번은 그걸 깜빡했을 때를 받아 주는 장치다.
