# LightNote 업데이트 지시서 — 업무 객체(구조화 필드) 도입

## 배경
LightNote는 현재 트리 구조(Projects/Areas/Resources/Archives + 업무 하위)와 리치 텍스트 편집기 기반의 개인 업무 노트 앱이다. 회사에서 업무 관리 용도로 실사용 중이며, 보안 정책상 회사 환경에서는 앱에 이미 구현된 AI 기능을 꺼서(off) 사용한다. 집에서는 향후 AI 기능을 켜서 사용할 계획이다.

지금까지 자유 기록 방식으로 업무를 기록해왔는데("ECR 생성 완료 / VTS 생성 완료 / 품질팀 확인 / 4M 변경으로 진행 / VPLM 아이템 생성 필요" 식의 누적 텍스트), 이 정보가 사람이 읽기엔 좋지만 "지금 뭘 해야 하는지", "언제까지인지", "무엇이 결정됐는지"를 한눈에 파악하기 어렵다는 문제가 있다.

## 목표
기존 자유 기록 방식(본문)은 그대로 유지하면서, 그 위에 **AI 없이도 완전히 동작하는 최소한의 구조화 필드("업무 객체")**를 추가한다. 이 구조는 회사(AI off)에서는 100% 수동 입력으로 쓰이고, 집(AI on)에서는 추후 AI가 같은 필드를 초안으로 채워주는 방식으로 확장될 수 있어야 한다. 즉 **데이터 모델은 하나, 입력 수단만 둘(수동 / AI 보조)**이 되도록 설계한다.

## 작업 시작 전 필수 확인사항 (Phase 0)
코드 작성에 들어가기 전에 반드시 먼저 다음을 조사하고 요약 보고할 것:
1. 현재 노트가 어떤 형식으로 저장되는지 (마크다운 파일 / DB / JSON 등), 저장 위치와 스키마
2. 현재 트리 구조(Projects/Areas/Resources/Archives, 업무 하위 4분류)가 코드상 어떻게 구현되어 있는지
3. 현재 AI on/off 토글이 어디서 관리되고, AI 관련 API 호출이 어느 코드 경로에서 트리거되는지 (신규 기능이 이 경로를 잘못 건드리지 않도록 파악 필수)
4. 현재 리치 텍스트 편집기가 어떤 라이브러리/구조인지
5. 앱이 어떤 플랫폼에서 동작하는지(웹/데스크톱 등), 화면 크기별 대응이 이미 되어 있는지
6. 회사 PC와 집 PC에서 각각 독립적으로 쓰는지, 아니면 데이터가 동기화(클라우드 저장/git 등)되는지 — 동기화되고 있다면 신규 메타데이터도 그 경로에 포함되는지 확인
7. 노트가 파일 경로/파일명 기준으로 식별되는지, 아니면 고유 ID 기준으로 식별되는지 확인 — 메타데이터를 노트가 이동되거나 이름이 바뀌어도 끊기지 않게 연결하려면 무엇을 기준으로 삼을지 결정 필요
8. 기존에 노트 검색 기능이 있다면, 신규 메타데이터 필드(관련부서, 결정사항 등)까지 검색 대상에 포함할지 확인 — 포함이 어려우면 이번 스코프에서는 제외하고 향후 과제로 남겨도 됨
9. 위 조사 결과와 아래 요구사항을 매핑한 구현 계획을 먼저 요약해서 제시하고, 구조적으로 애매하거나 기존 구조와 충돌하는 부분이 있으면 코드 작성 전에 먼저 질문할 것 (추측으로 진행하지 말 것)

## 설계 원칙
- 기존 트리 구조와 리치 텍스트 편집기는 제거·대체하지 않는다. 그 위에 얹는 방식이다.
- 구조는 최소한으로 — 무거운 DB 마이그레이션이나 별도 앱처럼 느껴지는 화면 전환은 지양한다.
- 회사 환경에서는 이 신규 기능의 어떤 경로도 AI API를 호출해서는 안 된다. AI 관련 코드는 이번 업데이트에서 건드리지 않는다(아래 "AI 연동 원칙" 참고).
- 기존 디자인 톤(색상, 폰트, 컴포넌트 스타일)을 그대로 따른다.

## 적용 범위(스코프) 및 노트 유형
- "업무 객체" 속성 패널은 **모든 노트에 강제 적용하지 않는다.** 노트 상단(또는 우측)에 "업무 속성 추가/제거" 토글을 두어, 사용자가 업무 성격의 노트에만 선택적으로 켤 수 있게 한다.
- "업무 속성 추가/제거" 토글에서 "제거"는 데이터를 즉시 삭제하는 것이 아니라 패널을 숨기는 것으로 동작한다. 입력해둔 값을 완전히 지우는 것은 별도의 명시적인 삭제 동작(확인 절차 포함)에서만 이뤄지도록 한다 — 실수로 토글을 껐다가 데이터를 잃는 일을 방지하기 위함.
- **전제 확인 필요:** 하나의 노트 페이지 = 하나의 업무 객체로 가정하고 설계한다(예: "공유기 설계 변경" 노트 하나에 속성 패널 하나). 다만 실제로 "메인 업무 정리" 같은 페이지 하나에 여러 업무가 나열되어 있을 수도 있으므로, Phase 0 조사 결과 이 가정이 맞지 않으면(한 페이지에 여러 업무가 섞여 있는 경우가 많으면) 노트 내 섹션 단위로 여러 업무 객체를 붙일 수 있는 구조가 필요한지 먼저 사용자에게 확인할 것.

## 데이터 모델 (업무 객체)
아래 필드를 정의한다. 필드명은 기존 코드 컨벤션(한글/영문)에 맞춰 조정 가능. **필수 입력 필드는 없다** — "상태"만 기본값(예정)을 가지고, 나머지는 모두 비워둔 채로 저장 가능해야 한다(입력 강제로 인한 사용 마찰 방지).

| 필드 | 타입 | 옵션/설명 |
|---|---|---|
| 상태 | 선택형 | 예정 / 진행중 / 대기 / 완료 / 보류 (기본값: 예정) |
| 우선순위 | 선택형 | 상 / 중 / 하 |
| 기한(Due) | 날짜 | 없어도 무방(선택) |
| 시작일 | 날짜 | 선택, 없으면 노트 생성일로 자동 기본값 |
| 최근수정일 | 날짜 | 자동 기록, 사용자가 속성을 수정할 때마다 갱신 |
| 완료일 | 날짜 | 상태를 "완료"로 바꾸는 순간 자동 기록. 완료에서 다른 상태로 되돌리면 완료일을 자동으로 지울지 유지할지 정책이 필요 — 기본값은 "유지, 사용자가 원하면 수동 삭제"로 한다 |
| 다음 Action | 체크리스트(배열) | 항목 추가/삭제/체크, 각 항목은 텍스트 + 완료여부 + (체크 시) 완료일 자동 기록 |
| 결정사항 | 로그(배열) | 날짜 자동 기록 + 내용. 기본은 새 항목 추가 방식으로 이력을 쌓는다. 단순 오타 수정 정도는 해당 항목을 편집할 수 있게 허용하되, 항목 전체 삭제는 별도 확인 절차를 거치게 하여 "왜 이렇게 결정됐는지" 이력이 실수로 지워지지 않게 함 |
| 관련 부서/담당 | 텍스트 또는 태그(선택) | 예: 품질팀, 인증팀 |
| 관련 문서 | 텍스트/링크(선택) | 예: ECR, VTS — 자유 텍스트로 시작해도 무방 |
| 관련 노트(내부 링크) | 링크(선택) | LightNote 내 다른 노트를 참조로 연결(예: ECR 관련 노트, VTS 관련 노트). 클릭하면 해당 노트로 이동. 필수 구현은 아니며 여력이 되면 포함(없어도 다음 Phase로 미뤄도 무방) |
| 업무 기록(본문) | 기존 리치 텍스트 | **변경 없음.** 지금처럼 자유롭게 기록하는 영역 그대로 유지 |

## UI 요구사항

### 업무 속성 패널
- 노트 본문 상단에 카드/패널 형태로 배치. 상태·우선순위·기한은 드롭다운/날짜피커로 즉시 편집 가능해야 한다(별도 저장 버튼 없이 즉시 반영 권장).
- "다음 Action"은 체크박스 리스트 UI. 항목 추가는 인라인 입력, 체크하면 취소선 처리 + 완료일 자동 기록.
- "결정사항"은 날짜별 로그 형태로 아래에 누적 표시(최신이 위 또는 아래는 기존 노트 관행에 맞춤).

### 상태 자동 로직
- 기한이 있고 오늘 날짜 기준 미완료 상태면 "D-n" 뱃지 표시.
- 기한이 지났고 상태가 "완료"가 아니면 자동으로 "⚠지연" 뱃지 표시(상태값 자체를 강제로 바꾸지는 않음, 시각적 경고만).
- 상태를 "완료"로 변경하면: ① 완료일 자동 기록 ② "완료 업무" 폴더로 이동할지 사용자에게 확인(자동 이동은 기본 off, 사용자가 선택했을 때만 이동 — 강제 이동 금지).

### 업무 목록/대시보드 뷰
- 트리와 별개로 "업무 목록" 화면(탭 또는 별도 뷰)을 추가. 업무 속성이 켜진 모든 노트를 표 형태로 렌더링: 제목 / 상태 / 우선순위 / 기한 / D-day / 최근수정일.
- 상태별/기한순/우선순위순 정렬·필터 지원.
- 요약 대시보드: 진행중 건수, 오늘 할 일 건수, 지연 건수, 이번 주 완료 건수를 상단에 숫자로 표시.
- 표의 각 행을 클릭하면 해당 노트로 이동.
- 수년간 누적되면 업무 노트 수가 수백 건 이상이 될 수 있으므로, 목록 뷰가 전체를 한 번에 무겁게 그리기보다 정렬/필터 후 필요한 만큼만 보여주는 방식(페이지네이션 등)을 고려할 것 — 다만 이번 Phase에서 필수 구현은 아니고, 체감상 느려질 때 대응해도 무방.

## AI 연동 원칙 (중요 — 보안)
- 이번 업데이트에서 AI 자동 채움 기능을 실제로 구현하지는 않는다. 다만 **향후 확장을 고려한 인터페이스만 마련**한다 — 예를 들어 속성 패널에 "AI로 채우기" 버튼 자리를 두되, 기존 AI on/off 토글이 off일 때는 이 버튼 자체가 보이지 않거나 비활성화되어야 한다.
- 신규 기능(속성 패널, 목록 뷰, 자동 뱃지 로직)의 어떤 코드 경로도 AI API를 호출하지 않아야 한다. 회사 환경에서 이 기능을 100% 안전하게 쓸 수 있어야 하는 것이 최우선 요구사항이다.
- 향후(이번 스코프 아님) AI가 켜졌을 때의 동작 방향만 참고로 남긴다: 자유 기록 텍스트를 분석해 상태/다음 Action/결정사항 초안을 제안 → 사용자가 항목별로 승인/수정/거부한 뒤에만 실제 필드에 반영(자동 덮어쓰기 금지). 이번 구현에서는 이 로직을 만들지 않는다.

## 기존 데이터 호환성
- 기존에 자유 텍스트로만 작성된 업무 노트는 새 필드가 모두 비어 있는 상태로 문제없이 열려야 한다. 강제 마이그레이션 없음.
- 사용자가 개별 노트에서 "업무 속성 추가" 토글을 켰을 때만 해당 노트에 속성 패널이 생성된다.
- 신규 필드는 본문(리치 텍스트) 데이터와 분리된 별도 메타데이터 영역에 저장해, 기존 본문 데이터나 렌더링 로직을 손상시키지 않도록 한다.
- 기존에 백업/동기화(클라우드 저장, git 등) 로직이 있다면 신규 메타데이터도 그 경로에 포함되어 유실되지 않도록 할 것.
- 노트를 삭제할 때 연결된 업무 속성 메타데이터도 함께 삭제되어, 참조 대상 없는 고아 데이터가 남지 않도록 할 것.
- 노트를 이동하거나 이름을 바꿔도 연결된 업무 속성이 끊기지 않도록, 메타데이터는 파일 경로/파일명이 아니라 노트의 고유 ID를 기준으로 연결한다.
- 노트 복제(복사) 기능이 있다면, 복제된 노트는 업무 속성이 빈 상태로 시작한다(원본의 진행 이력·결정사항이 그대로 복사되지 않도록).

## 안정성/예외 처리
- 업무 속성 메타데이터 저장 또는 로드에 실패해도 노트 본문의 열람·편집은 영향받지 않아야 한다(속성 패널만 별도로 오류 상태를 표시).
- 저장 실패를 조용히 무시하지 말고 사용자에게 알릴 것.
- 동시 편집 충돌 처리는 이번 스코프 밖으로 본다 — 개인 단일 사용자가 한 번에 한 기기에서 사용한다고 가정한다.

## 구현 단계 (Phase 1~4)
1. **Phase 1**: 데이터 스키마 설계 + 저장 구조 구현 (Phase 0 조사 결과 기반)
2. **Phase 2**: 업무 속성 패널 UI (상태/우선순위/기한/다음 Action/결정사항/관련부서/관련문서 수동 입력) + 노트별 토글 켜고 끄기
3. **Phase 3**: 자동 계산 로직 (D-day 뱃지, 지연 뱃지, 완료 처리 시 완료일 자동기록 및 이동 확인)
4. **Phase 4**: 업무 목록/대시보드 뷰 (표, 필터/정렬, 요약 카운트)

각 Phase 완료 시마다 결과를 보여주고 다음 Phase로 넘어가기 전에 확인을 받을 것. (한 번에 전체를 구현해서 리뷰 없이 밀어붙이지 말 것)

## 하지 말아야 할 것 (Non-goals / Guardrails)
- 기존 트리 구조·리치 텍스트 편집기 교체 금지
- Excel/Word 파일 자동 생성·내보내기 기능은 이번 스코프 아님 (필요 시 별도 논의)
- AI 자동 채움 기능의 실제 구현은 이번 스코프 아님 — 버튼/인터페이스 자리만
- 기존 AI on/off 토글 로직 변경 금지
- 기존 노트를 강제로 새 스키마로 마이그레이션하는 로직 금지
- 기한 임박/지연에 대한 푸시 알림·리마인더 기능은 이번 스코프 아님 (화면 내 D-day·지연 뱃지 표시로 충분, 별도 알림 시스템은 향후 논의)

## 완료 조건 체크리스트
- [ ] 업무 속성이 꺼진 상태의 기존 노트는 이전과 동일하게 동작하는가
- [ ] 회사 환경(AI off)에서 신규 기능 전체가 AI 호출 없이 완전히 동작하는가
- [ ] 상태/우선순위/기한/다음 Action/결정사항을 수동으로 입력·수정·삭제할 수 있는가
- [ ] 기한 경과 시 지연 뱃지가, 완료 처리 시 완료일이 자동으로 기록되는가
- [ ] 업무 목록 뷰에서 필터/정렬과 요약 카운트가 정확히 동작하는가
- [ ] 결정사항 로그가 삭제되지 않고 이력으로 누적되는가
- [ ] 구조가 모호한 지점(1노트=1업무 가정 등)에 대해 사전에 확인을 받았는가
- [ ] 노트 삭제 시 연결된 업무 속성 메타데이터도 함께 삭제되는가
- [ ] 기존 백업/동기화 경로가 있다면 신규 메타데이터도 그 경로에 포함되는가
- [ ] 완료 상태를 되돌렸을 때 완료일 필드가 정책대로(기본: 유지) 처리되는가
- [ ] 노트를 이동하거나 이름을 바꿔도 업무 속성 연결이 끊기지 않는가 (고유 ID 기준)
- [ ] 메타데이터 저장/로드에 실패해도 노트 본문은 정상 동작하고, 사용자에게 오류가 안내되는가
- [ ] 업무 속성 토글을 꺼도 입력해둔 데이터가 즉시 삭제되지 않고 보존되는가 (완전 삭제는 별도 확인 절차 필요)
- [ ] 상태 외 모든 필드가 비어 있어도 저장·사용에 문제가 없는가 (필수 입력 강제 없음)

## 마무리 지시
구현 완료 후, 새로 추가된 기능의 사용법(업무 속성 켜는 법, 각 필드의 의미, 업무 목록 뷰 위치와 사용법 등)을 간단히 요약해서 알려줄 것.
