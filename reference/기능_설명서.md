## 1. 앱의 목적

일반적인 일정 관리 앱은 "따로 열어야 보이는" 창이라 확인을 미루게 되기 쉽다.
Daily Sidebar Planner는 이 문제를 **화면 가장자리에 항상 떠 있는 얇은 사이드바**로
풀었다 — 별도로 창을 열지 않아도 오늘 할 일과 다가오는 일정이 시야 구석에
상시 노출된다. 필요할 때만 클릭해서 펼치고, 더 깊은 관리(월간 뷰, 습관,
포커스 세션, 통계 등)가 필요하면 별도의 대시보드 창을 연다.

여기에 더해, 업무 중 떠오르는 생각·회의록·리서치를 즉시 정리할 수 있도록
**LightNote**라는 완전한 노트 필기 앱을 내부에 통합했다. 일정·태스크와
노트를 하나의 앱 생태계 안에서 오가며 쓸 수 있다는 것이 이 프로젝트의
핵심 가치다.

## 2. 전체 아키텍처

### 2.1 창 구조

메인 프로세스(`src/main/index.ts`)가 여러 개의 `BrowserWindow`를 필요에
따라 생성한다. 모두 같은 `renderer/index.html`을 URL 해시로 구분해
로드하는 방식(멀티 엔트리)이며, 하나의 preload(`preload/index.js`,
`contextIsolation:true / nodeIntegration:false`)를 공유한다. 단,
LightNote만 별도 preload(`preload/lightnote.js`)를 쓴다.

| 창 | 변수명 | 트리거 | 크기 | 특징 |
|---|---|---|---|---|
| **사이드바** | `mainWindow` | 앱 시작 시 항상 생성 | 접힘: 폭 32/40/52px × 콘텐츠에 맞춰 자동 측정된 높이. 펼침: `+300px` × 최대 580px | `alwaysOnTop:'screen-saver'`, `skipTaskbar`, `transparent`, `frame:false`, 모든 가상 데스크톱에서 보임. 해시 `/` |
| **대시보드** | `dashboardWindow` | 사이드바 그리드 아이콘, 트레이 "Open Dashboard", `D` 키 | 960×700, 최소 800×560 | 일반 타이틀 창, 해시 `#dashboard` |
| **커맨드 팔레트** | `paletteWindow` | `Ctrl/Cmd+K`(사이드바·대시보드 어디서든), 사이드바 검색 아이콘 | 640×460 | 프레임 없는 오버레이, 해시 `#palette`, 포커스를 잃으면 자동 닫힘 |
| **이벤트/태스크 편집기** | `editorWindow` | `N`(새 이벤트), `Shift+N`(새 태스크), "+" 버튼, 항목의 "⋯"메뉴 편집 | 460×680 | 프레임 없는 오버레이(`EventModal`/`TaskModal` 전체화면 호스팅), 해시 `#editor`, 포커스 잃으면 닫힘(단, 노트 에디터 자식 창이 포커스면 예외) |
| **노트 에디터(플래너 자체)** | `noteEditorWindow` | IPC로만 정의, **현재 어떤 UI에서도 호출되지 않음** — 사실상 미사용/레거시(§15 참고) | 480×640 | 해시 `#note` |
| **퀵 캡처** | `captureWindow` | 전역 단축키 `Ctrl+Shift+Space` | 560×140, 화면 상단에서 약 22% 지점 | 프레임 없는 오버레이, 해시 `#capture`, 포커스 잃으면 닫힘 |
| **LightNote** | `lightNoteWindow` | 사이드바 노트 아이콘, `lightnote://` 딥링크 | 1280×800, 최소 960×600 | 별도 preload, 해시 `#lightnote` |

앱 전역에서 `http/https/mailto/tel` 링크로의 인앱 네비게이션은 가로채서
시스템 기본 브라우저로 열도록 강제한다(내부 화면이 외부 링크로
덮어씌워지는 것을 방지).

### 2.2 데이터 흐름 요약

```
사이드바 ──┐
           ├─ IPC ─→ src/main/db/storage.ts ─→ planner.json (이벤트·태스크·습관·Focus Area)
대시보드 ──┘

LightNote ─ IPC ─→ src/main/lightnote/*.js ─→ %APPDATA%/lightnote/lightnote-data/*.json
                                            └─(선택적 브릿지)→ storage.ts (태스크 생성/완료 동기화 — 현재 UI에서 숨김, §17.3)

이벤트/태스크 편집창(NoteLinksSection) ──IPC──→ LightNote 페이지 생성/연결/AI 요약(§15)
```

## 3. 사이드바 위젯

`src/renderer/src/App.tsx` + `components/Sidebar.tsx` + `components/Panel.tsx`.

### 3.1 접힌 상태(기본)

화면 가장자리(좌/우, `settings.edge`)에 붙는 얇은 세로 바. 폭은
32/40/52px 중 설정값, 높이는 콘텐츠를 실측(`ResizeObserver`)해 자동
조절된다. 위에서 아래로:

1. 드래그 핸들(잠금 해제 상태일 때만 표시)
2. 날짜 블록(요일 / 일 / 월)
3. 구분선
4. 퀵 팔레트 아이콘 (`Ctrl/Cmd+K`)
5. 대시보드(그리드) 아이콘
6. 오늘(캘린더) 아이콘 — 이미 오늘 화면이면 강조색으로 표시
7. 노트(LightNote 열기) 아이콘
8. 도움말("?") 아이콘 — 대시보드의 Help 탭으로 이동
9. *(포커스 타이머 동작 중일 때만)* 🎯/⏸ + mm:ss 미니 표시 — 클릭으로 일시정지/재개
10. 잠금/잠금해제 토글 버튼

### 3.2 펼친 상태

스트립에 마우스를 올리면(hover) 옆으로 300px 폭 **패널**이 열린다(스트립
위치가 안 흔들리도록, 세로 공간이 남는 쪽으로 열림). 패널 내용(스크롤
가능):

- **DateCard** — 큰 날짜 표시, 이전/다음 날 화살표, 네이티브 날짜 선택기,
  "오늘로 이동" 칩
- **Timeline** — 오늘의 이벤트 목록 + "+"로 추가
- **TaskBoard** — 선택한 날짜의 마감 태스크 + 접이식 "기타"(지연/예정/
  Inbox/최근 완료), Rollover 버튼, **일괄 빠른 추가**(한 줄에 하나씩,
  최대 5개, 마감일 없이 Inbox로 등록)
- **FocusTimer** — 인라인 포모도로/스톱워치 위젯(§8)

마우스가 스트립·패널 모두를 벗어나면 400ms 후 축소 타이머가 시작되고,
부드러운 전환을 위해 220ms 더 지난 뒤 실제로 창 크기를 줄인다.

### 3.3 위치·잠금·모드

- **드래그 이동**: 잠금 해제 상태에서 스트립 상단 그립을 드래그하면 창
  전체가 이동한다. 이동 후 Y 오프셋이 `customY`로 저장된다(잠금 시
  저장 안 함).
- **잠금(Lock)**: 스트립의 자물쇠 버튼으로 `settings.locked` 토글.
  잠그면 드래그 핸들이 사라지고 `setMovable(false)`. **기본값은
  잠금 해제.** 전용 단축키는 없음 — 클릭으로만 전환.
- **피크 모드(클릭 통과)**: 설정의 `clickThrough`를 켜면 사이드바
  전체가 마우스 이벤트를 무시(클릭이 뒤 창으로 통과)하고 40% 투명도로
  흐려진다. `Ctrl+Shift+S`로 일시적으로 다시 상호작용 가능한 상태(완전
  불투명)로 깨울 수 있고, 다시 누르면 통과 모드로 복귀하며 펼쳐져
  있었다면 자동으로 접힌다.
- **가장자리(edge)**: 좌/우 선택, 사이드바·패널이 그에 맞춰 재배치.
- **크기**: 접힘 폭은 32/40/52px 고정 3종, 패널은 항상 300px 고정,
  전체 창 높이는 최대 580px이며 화면 작업영역보다 작은 쪽에 맞춰진다.
- **멀티 모니터**: `settings.displayId`로 특정 모니터에 고정 가능(설정
  화면에서 선택). 디스플레이 구성이 바뀌면 자동으로 재배치.

### 3.4 키보드 단축키 (사이드바 포커스 시, 입력창 포커스 중이 아닐 때)

| 키 | 동작 |
|---|---|
| `Ctrl/Cmd+K` | 커맨드 팔레트 |
| `D` | 대시보드 열기 |
| `T` | 오늘로 이동 |
| `N` | 새 이벤트 |
| `Shift+N` | 새 태스크 |
| `Esc` | 패널 접기 |

## 4. 대시보드 창 개관

`DashboardApp.tsx`가 셸 역할 — 상단 2단 헤더(탭 스트립 + 날짜 이동/퀵
추가/이벤트 추가/태스크 추가/새로고침), 본문에 11개 탭을 전환:
`today | day | week | month | review | tasks | focus | insights |
habits | help | settings`.

포커스 시 단축키: `Ctrl/Cmd+K` 팔레트, `T` 오늘, `M` 월간, `W` 주간,
`D` 일간, `N` 새 이벤트, `Shift+N` 새 태스크.

- **Today** — 오늘 하루의 "브리핑" 화면. 시간대별 문구가 바뀌는 안내
  배너(아침 "오늘 계획하기" / 낮 "Today" / 저녁 "저녁 리뷰" + 지연
  태스크 있으면 "↪ N개 이월" 버튼), **Workload 카드**(필요 작업시간 대비
  남은 가용시간 진행바, "초과예약" 배지, 이벤트/태스크 개수), 그리고
  4개 카드 — 오늘의 이벤트 / 지연된 태스크 / 오늘 마감 / Inbox(마감일
  없는 태스크, 최대 8개) — 클릭 시 편집창, 인라인 완료 토글 가능.
- **Day / Week** — 같은 컴포넌트(`WeekView`)가 `dayMode`로 1일/7일
  전환. 시간당 56px 그리드, 드래그로 이벤트 이동(요일 간 이동도 가능,
  실시간 미리보기), 아래쪽 모서리 드래그로 종료시간 리사이즈(15분
  단위 스냅, 최소 표시 높이 ~22px), 현재 시각 빨간 선, 겹치는 이벤트
  나란히 배치. 하단에 크기 조절 가능한 **태스크 패널**(오늘/선택일/
  미완료/지연/완료/Inbox 필터 칩) — **태스크를 캘린더로 드래그하면
  자동으로 시간 블록 이벤트 생성**(기본 60분 또는 예상시간)되고
  태스크는 완료 처리됨.
- **Month** — 6주 그리드. 셀마다 태스크 우선순위 점(최대 5개), 이벤트
  칩(최대 3개+"N more"), 드래그&드롭으로 이벤트 날짜 변경(반복
  이벤트는 범위 확인 프롬프트), 날짜 클릭 시 해당 Day 뷰로 이동.
- **Review(위클리 리뷰)** — §11.
- **Tasks** — 날짜와 무관한 전체 태스크 목록, 필터 칩(전체/오늘/지연/
  예정/Inbox/완료)마다 실시간 개수 표시, "+ 태스크 추가".
- **Focus** — Focus Area(프로젝트 그룹) 관리 화면. §8의 포커스
  **타이머**와는 다른 기능이니 주의 — §7 참고.
- **Insights** — §10.
- **Habits** — §9.
- **Settings** — §14.
- **Help** — 앱 내 사용법 안내(한국어), 기본/이벤트&태스크/집중&습관/
  노트/캘린더데이터 섹션으로 구성, 단축키도 함께 표기.

## 5. 태스크 관리

`TaskRow` (`src/main/db/storage.ts`) 기준. 편집은 `TaskModal.tsx`,
표시는 `TaskItem.tsx`(사이드바·TasksView 공용).

| 필드 | 설명 |
|---|---|
| `title` | 제목 |
| `due_at` | 마감(선택한 날짜의 23:59:59.999로 저장). 없으면 Inbox |
| `priority` | urgent / normal / low (3버튼 선택) |
| `projects` | 다중 선택 태그(Notion 스타일 칩, 새 태그 인라인 생성 가능). 레거시 단일 `project`는 `projects[0]`로 항상 동기화 |
| `focus_area_id` | 연결된 Focus Area(§7) |
| `recurrence` | 반복 규칙(JSON) |
| `estimated_minutes` / `actual_minutes` | 예상 소요시간(시/분 입력) / 포커스 타이머로 누적된 실제 작업시간 |
| `subtasks` | 체크리스트(`{id, title, done}`) |

**반복**: 매일/매주(요일 다중선택)/매월/매년, 종료조건(무기한/N회/
날짜). 마감일이 있어야 반복 설정 가능. 반복 태스크를 완료 체크해도
바로 끝나지 않고 **다음 회차로 마감일이 자동 이동**(종료조건 도달
시에만 최종 완료 처리).

**Rollover**: 지연되고 미완료인 비반복 태스크를 오늘 날짜로 일괄 이월.
Today 뷰, TaskBoard의 지연 섹션 등 여러 곳에 "↪ N개 이월" 버튼으로 노출.

**일괄 빠른 추가**: 텍스트 영역에 한 줄당 하나씩(최대 5줄),
`Ctrl/Cmd+Enter`로 제출, 모두 Inbox(마감 없음, normal 우선순위)로 등록.

**스누즈**: 항목 "⋯" 메뉴에서 +2시간 / 오늘 저녁 6시 / 오늘 / 내일 /
이번 주말(다음 토 9시) / 다음 주 / 마감일 지우기.

**시간 블록화**: "⋯ → 시간 블록(다음 시간)"으로 태스크를 1시간(또는
예상시간)짜리 캘린더 이벤트로 전환. 주간/일간 뷰 캘린더로 태스크를
드래그해도 동일하게 동작.

**포커스 타이머 연동**: 포커스 세션을 "정지 & 기록"하면 그 시간이
`actual_minutes`에 누적(§8).

**검색**: 제목/프로젝트 태그 부분 일치로 커맨드 팔레트에서 검색됨.

`EventRow` 기준. 편집은 `EventModal.tsx`.

| 필드 | 설명 |
|---|---|

| `recurrence` | 태스크와 동일한 규칙 구조 |
| `reminder_minutes` | 끄기 / 시작 시 / 5·10·15·30분 전 / 1시간 전 |

- **반복 이벤트**: 조회 범위에 맞춰 가상 인스턴스로 확장되어 표시(최대

  시엔 "전체 삭제" 옵션도 있음.
- **충돌 감지**: 편집 중 같은 날짜의 다른 이벤트와 겹치면(최대 3개)
  경고 배너로 표시(자기 자신·같은 시리즈의 다른 회차는 제외).
- **드래그/리사이즈**(주/일 뷰): 드래그로 이동(요일 간 이동 포함,

- **ICS 가져오기/내보내기**: 설정 → Calendar(.ics)에서 파일로 가져오기/

  연동용).
- **리마인더**: 시작 전 알림이 일일 브리핑과 별개로 개별 스케줄링됨(§13).

## 7. Focus Areas (프로젝트 그룹)

대시보드의 **Focus 탭**은 포모도로 타이머가 아니라 **프로젝트/OKR형
그룹 관리 화면**이다(포커스 *타이머*는 §8, 사이드바에 있음 — 이름이
비슷해 혼동하기 쉬우니 주의).

- Focus Area 생성/수정/보관(archive)/삭제 — 제목, 8색 팔레트에서 색상,
  선택적 마감일.
- 영역별 통계: 완료/전체 태스크 수, 이벤트 개수, 진행률 막대, 지연

- Active / Archived("완료") 탭으로 구분.
- 태스크·이벤트를 이 그룹에 연결하면(`focus_area_id`) 위클리 리뷰의
  "Focus Tree"(§11)와 인사이트(§10)의 프로젝트별 집중시간 집계에
  반영된다.

## 8. 포커스 타이머(뽀모도로)

`components/MainView/FocusTimer.tsx`(사이드바 패널) + `focusStore.ts`
(Zustand 전역 상태 — 접힌 스트립에서도 경과시간을 보여주기 위함).

- **두 가지 모드**: `countdown`(설정 시간에서 카운트다운, 뽀모도로형)과
  `countup`(단순 스톱워치, 무한 카운트업). 모드 전환은 정지 상태에서만
  가능.
- **카운트다운 프리셋**: 15 / 25 / 45 / 60분, 또는 직접 입력(1~600분).
  기본값 25분.
- **태스크 선택**: 미완료 태스크 중 선택해야 시작 가능.
- **컨트롤**: 시작/재개(▶) · 일시정지(⏸) · 정지 & 기록(⏹). 카운트다운이
  0에 도달하면 자동으로 "정지 & 기록" 처리.
- **태스크 연동**: 정지 시 경과 분(0.1분 단위 반올림)을 선택한
  태스크의 `actual_minutes`에 누적. 이 값이 인사이트의 "집중 시간"
  집계의 유일한 원천이다.
- **사이드바 미니 표시**: 타이머가 동작 중이거나 경과시간이 있으면
  접힌 스트립에도 🎯/⏸ + mm:ss가 표시되며, 클릭만으로 패널을 열지
  않고도 일시정지/재개 가능.

## 12. 퀵 캡처 · 커맨드 팔레트

### 12.1 퀵 캡처 (`Ctrl+Shift+Space`)

화면에 뜨는 한 줄짜리 프레임 없는 입력창. 입력을 `lib/nlParser.ts`(한/영
이중언어 자연어 파서)로 해석한다 — "오늘/내일/모레/어제" 및
"today/tomorrow", "다음 주 X요일"/"next X", 월-일 및 M/D 날짜, 한/영
오전·오후 + "X시 Y분"/HH:MM/h-pm 시간 표기, "1시간 30분"/"1h"/"90m" 같은
기간 표현을 인식한다. 입력 중 실시간 미리보기 줄에 무엇이 생성될지
표시("📋 Task: … · 마감 …" 또는 "📅 Event: … · 일시"). 시작 시각이
파싱되면 **이벤트**로, 아니면 **태스크**(마감 있음/없음)로 생성된다.
`Enter`로 확정 및 닫기, `Esc`로 취소.

### 12.2 커맨드 팔레트 (`Ctrl/Cmd+K`)

검색창 하나로 동시에 세 가지 역할:
1. 입력 텍스트를 자연어 파싱해 즉석에서 태스크/이벤트 생성 제안
   (퀵 캡처와 같은 파서 사용)
2. 기존 이벤트/태스크를 제목/장소/설명/프로젝트 기준으로 실시간
   검색(120ms 디바운스)
3. 정적 내비게이션 명령 — "대시보드 열기"(D), "오늘로 이동"(T),
   "새 이벤트(편집기)"(N), "새 태스크(편집기)"(Shift+N) — 이 항목들은
   즉시 생성 대신 전체 편집창을 연다.

방향키로 탐색, `Enter`로 실행, `Esc`로 닫기. 검색 결과를 선택하면 호출한
창(사이드바 또는 대시보드)이 해당 날짜로 이동한다.

## 13. 알림/리마인더

두 가지 독립적인 스케줄링 메커니즘.

1. **일일 브리핑**: **오전 9시("Morning Briefing")**와 **오후 1시("Midday
   Check-in")**에 고정 발송(`settings.reminderEnabled`가 true일 때만).
   본문은 `computeWorkload()` 기반 — "N개 이벤트 · M개 태스크 남음",
   "필요 X시간 / 여유 Y시간(Z%)", 초과예약 경고 또는 "✓ 여유 있음", 시간
   미지정 태스크 개수 각주. 알림 클릭 시 대시보드가 열린다.
   `reminderEnabled`/`workStartHour`/`workEndHour` 설정이 바뀌면 자동
   재스케줄.
2. **이벤트 개별 리마인더**: 향후 24시간 내 이벤트(반복 확장 포함) 중
   `reminder_minutes`가 설정된 것마다 "N분 후 시작"(또는 "지금 시작")
   알림. 데이터가 바뀔 때마다 재계산되고, 24시간 경계 밖 항목을
   놓치지 않도록 15분마다 재스캔.

**Workload**(Today 카드·브리핑 공통 사용) = 업무 종료시각까지 남은
분(分) 대비, 오늘 남은 이벤트 + 마감/지연 태스크의 예상 소요시간 합.

## 15. 이벤트/태스크 ↔ LightNote 노트 연결

플래너 자체에도 예전에 쓰던 네이티브 노트 저장소(`NoteRow`, 관련
IPC/전용 편집창 `#note`)가 코드에 남아 있지만, **현재 어떤 화면에서도
호출되지 않는 사실상 레거시**다. 실제로 사용자가 쓰는 노트 기능은
전부 **LightNote로 통합**되어 있다.

이벤트/태스크 편집창 하단의 **`NoteLinksSection`**이 그 연결
지점이다(주석 그대로: *"LightNote 페이지(진짜 노트)를 이벤트/태스크에
연결한다. 옛 플래너 자체 노트 시스템을 대체."*):

- **🔗 연결**: 기존 LightNote 페이지를 검색해 현재 이벤트/태스크에 연결.
- **+ New**: 그 항목의 제목과 일시(배정 시각 또는 마감일)를 미리 채운
  새 LightNote 페이지를 생성하고 즉시 LightNote 창에서 열어준다.
- 연결된 페이지는 칩으로 표시되며 클릭 시 LightNote에서 해당 페이지가
  열림, 칩의 ×로 연결 해제.
- **✨ Brief**: 연결된 LightNote 페이지들의 내용을 바탕으로 AI가 요약을
  생성(`aiBrief` IPC). **LightNote에 Gemini API 키가 설정되어 있어야
  동작**하며, 없으면 "AI API 키를 설정하세요" 안내만 표시된다.
- 반대 방향으로, LightNote 페이지 안에도 "LINKED" 섹션이 있어 그
  페이지가 어떤 이벤트/태스크에 연결됐는지(날짜/마감 정보 포함)
  보여준다.

## 16. LightNote — 임베디드 노트 앱

`src/renderer/src/lightnote/` (렌더러) + `src/main/lightnote/` (메인, CJS
모듈). Quill 2.0.3 리치 텍스트 에디터 기반의 완결된 노트 필기 앱으로,
독립 창(`#lightnote`)에서 실행된다.

### 16.1 구조 — 노트북 › 섹션 › 페이지

- **노트북(Notebook)**: 최상위 분류, 색상 지정 가능, 고정(pin) 가능.
- **섹션(Section)**: 노트북 하위 폴더. 중첩(하위 섹션) 지원.
- **페이지(Page)**: 실제 노트 한 장. 고유 UUID로 식별되어 이동/이름변경
  후에도 메타데이터(업무 객체, 참조 링크 등)가 유지된다.
- 트리 UI(`NotebookTree.tsx`)에서 드래그로 페이지 순서 변경, 노트북/섹션
  간 이동 가능.
- 업무 속성이 부여된 페이지는 좌측 트리에서 **📋** 아이콘으로 표시되어,
  일반 메모 페이지와 한눈에 구분된다(§17).

### 16.2 에디터 기능 (`Editor.tsx`)

- **서식**: 굵게/기울임/밑줄/취소선, 글자 크기(px 단위 임의값), 글자색/
  배경색(Word 스타일 팔레트), 헤딩(H1~H3), 인용구, 코드 블록.
- **목록**: 글머리 기호, 번호 매기기(임의 시작 번호 직접 입력 가능 —
  타이핑한 숫자 그대로 시작), Word 스타일 자동 목록 인식(`1.` + 스페이스 →
  자동 번호 목록, Ctrl+Z로 되돌리기 가능), 체크박스(OneNote 스타일,
  체크 시 ✓ 표시).
- **목차 수준(Outline level)**: 문단에 목차 수준(목차1~목차3 등)을 지정하면
  왼쪽에 수준별 색상 바가 표시되고, 우측 목차 패널(`TocPanel.tsx`)에 자동
  반영된다. 목차 항목은 드래그로 순서 변경(하위 내용 포함), 접기/펼치기
  지원(공백 줄을 접기 경계로 인식), 폴드 상태는 페이지별로 저장되어
  재방문 시 유지된다.
- **정렬**: 왼쪽/가운데/오른쪽. 표 안에서는 표 전체가 아니라 **커서가 놓인
  셀(또는 드래그로 선택한 셀 범위)** 에 적용된다.
- **위/아래 첨자**: x², H₂O 같은 표기.
- **서식 복사(Format Painter)**: 버튼을 누르면 현재 선택의 인라인 서식을
  "집어오고", 다음에 드래그하는 범위에 그대로 붙인 뒤 자동 해제된다
  (한 번 더 누르면 취소). Word의 서식 복사와 동일하게, 기존 서식을
  합치지 않고 **덮어쓴다**.
- **한글 다단계 번호**: 들여쓰기 수준에 따라 `1.` → `가.` → `1)` → `가)`
  순으로 자동 전환되어 국내 문서 서식 그대로 쓸 수 있다.
- **표(테이블)**: `quill-table-up` 플러그인으로 행/열 삽입, 셀 병합/분리,
  셀 경계 드래그로 크기 조절. 엑셀/Word에서 복사한 표를 그대로
  붙여넣기 지원. 여러 셀을 드래그 선택한 뒤 글자 크기·정렬을 바꾸면
  선택한 셀 전체에 적용된다.
  - **표 스타일 프리셋**: 툴바 `표 스타일` → *머리행 강조* / *머리행 +
    줄무늬* / *스타일 지우기*. 첫 행에 배경색 + 굵게, 줄무늬는 짝수 본문
    행에 옅은 배경을 더한다. 프리셋은 표 전체를 **인쇄물 같은 밝은 표**로
    통일한다 — 배경만 칠하면 다크 테마에서 밝은 배경 위에 밝은 글자가 남아
    읽을 수 없으므로, 배경과 글자색을 항상 같이 바꾼다. 건드리는 것은
    **셀 배경 · 글자색 · 머리행 굵게** 뿐이라 *스타일 지우기*로 언제든
    테마 기본 모습으로 되돌아간다.
  - **텍스트 → 표(`⇥▦`)**: 여러 줄을 선택하고 누르면 탭(탭이 없으면 쉼표)
    기준으로 열을 나눠 표로 바꾼다. 엑셀에서 복사해 붙여넣은 텍스트가
    그대로 표가 된다(최대 100행 × 30열).
  - **표 → 텍스트(`▦⇤`)**: 커서가 놓인 표를 탭 구분 텍스트로 되돌린다.
- **파일 첨부(`📎`)**: 파일을 고르면 페이지 전용 폴더로 복사되고 본문에는
  링크만 남는다. 링크를 누르면 연결 프로그램으로 열린다(§16.10).
- **글자 수**: 편집기 하단에 글자 수/단어 수가 실시간 표시된다.
- **이미지**: 삽입/붙여넣기 지원. AI Organize 처리 시에도 이미지가
  유실되지 않고 보존된다.
- **줄 높이**: 한 줄 안의 최대 글자 크기에 맞춰 줄 간격이 자동 조절.

### 16.3 검색 · 목차

- 상단 검색창에서 여러 단어를 공백/쉼표/마침표로 구분해 입력하면
  **AND 조건**으로 전체 노트를 검색(`SearchBar.tsx`).
- 우측 목차 패널이 현재 페이지의 헤딩·목차 수준 문단을 실시간으로
  보여주며, 클릭 시 해당 위치로 스크롤 이동.

### 16.4 휴지통(Trash)

- 노트북/섹션/페이지 무엇을 삭제하든 **삭제 당시 그대로의 구조**를
  유지한 채 휴지통으로 이동(하위 트리 전체 보존, 내용도 그대로 보임).
- 좌측 트리 하단에 고정된 휴지통 패널에서 각 삭제 항목을 펼쳐보고,
  개별 복원(restore) 또는 영구 삭제(purge) 가능, 전체 비우기도 지원.
- **보관 기간(retention)**: 기본 30일, 설정에서 변경 가능. 기간이 지나면
  자동으로 영구 삭제된다(백그라운드 purge 루프). 휴지통에 있는 동안은
  업무 객체 데이터도 함께 보존되고, 영구 삭제 시에만 완전히 제거된다.

### 16.5 AI 어시스턴트 (`AIAssistant.tsx`)

Google Gemini API 연동 — **API 키가 등록된 경우에만 활성화**되는 기능들:

- **질문/검색**: 현재까지 작성한 노트 전체를 대상으로 질문에 답변(선택적으로
  웹 검색도 결합), 출처를 각주([1][2]…)로 표시하고 답변을 노트로 삽입 가능.
- **AI Organize**: 현재 페이지의 텍스트를 정리된 구조로 재구성(이미지는
  맥락에 맞게 재배치되어 보존됨).
- **일정/할일 추출**: 노트 텍스트에서 태스크·이벤트 후보를 추출해
  플래너에 바로 등록.

> 회사 환경처럼 API 키가 없는 경우 이 기능들은 모두 자동으로 비활성화된다.
> 별도의 "AI on/off" 스위치는 없고, **API 키 존재 여부가 곧 게이트**다.
> §15의 "✨ Brief"(이벤트/태스크 요약)도 같은 키를 사용한다.

### 16.6 설정 · 외관

`SettingsModal.tsx`에서:
- **테마** 5종(Dark/Light/Sepia/OLED/Forest), **강조색** 6종, **에디터 폰트**
  5종(Sans/Serif/Mono/Rounded/System) — 즉시 미리보기 적용, `localStorage`에 저장.
- **Gemini API 키** 등록/검증/삭제.
- **중복 페이지 정리(Dedup)**: 인덱스 꼬임 등으로 생긴 중복 페이지를
  자동 정리.

### 16.7 페이지 링크

페이지 하단 "RELATED PAGES"에서 다른 LightNote 페이지를 서로 연결
(양방향 참조)할 수 있고, §15의 `NoteLinksSection`을 통해 플래너의
이벤트/태스크와도 연결된다.

### 16.8 찾기·바꾸기

`Ctrl+F`로 현재 페이지 안에서 찾기 바를 연다. 일치 항목 수와 현재 위치
(`3 / 12`)가 표시되고, `Enter`/`Shift+Enter`로 다음·이전으로 이동한다.
바꾸기 칸에 입력하면 **하나만 바꾸기**와 **모두 바꾸기**를 쓸 수 있다.

### 16.9 버전 기록 (`🕘 버전`)

- 페이지를 저장할 때마다 **직전 내용**을 자동으로 스냅샷한다.
- 저장 폭주를 막기 위해 **최소 3분 간격**으로만 새 버전을 남기고,
  내용이 실제로 바뀌지 않았으면 남기지 않는다.
- 페이지당 최근 **30개**까지 보관하며, 그보다 오래된 것은 자동 삭제된다.
- 편집기 우상단 `🕘 버전` 버튼에서 버전 목록을 열어 내용을 미리 보고,
  원하는 시점으로 **되돌리기**할 수 있다. 되돌리기 직전 상태도 새 버전으로
  남으므로 되돌리기 자체를 취소할 수 있다.
- 페이지를 영구 삭제하면 그 페이지의 버전 기록도 함께 지워진다.

### 16.10 파일 첨부

- 툴바 `📎` → 파일 선택. 고른 파일은 원본을 건드리지 않고
  `%APPDATA%/lightnote/lightnote-data/attachments/<pageId>/` 아래로
  **복사**되므로, 원본을 옮기거나 지워도 노트의 첨부는 살아 있다.
- 본문에는 `📎 파일명` 링크만 삽입된다. 클릭하면 OS 기본 연결 프로그램으로
  열리고, 우클릭으로 탐색기에서 위치 보기도 가능하다.
- 페이지를 영구 삭제하면 그 페이지의 첨부 폴더도 함께 정리된다.

### 16.11 PDF 내보내기 (`🖨 PDF`)

현재 페이지를 그대로 PDF로 저장한다. 화면에 보이는 서식(표·색·이미지·
글자 크기)이 유지되며, 저장 위치는 시스템 저장 대화상자에서 고른다.

### 16.12 하위 페이지 · 페이지 템플릿

- **하위 페이지**: 페이지 우클릭 → `📑 하위 페이지 추가`. 트리에서 부모
  아래에 한 단계 들여써서 표시되고, 손자 페이지까지 계층이 유지된다.
- **페이지 템플릿**: 페이지 우클릭 → `💾 템플릿으로 저장`으로 현재 페이지
  내용을 양식으로 저장하고, 섹션 우클릭 → `📑 템플릿에서 페이지 추가`로
  그 양식으로 새 페이지를 만든다. 업무 페이지 뼈대(배경/목적/진행 현황)를
  한 번 만들어 두고 계속 재사용하는 용도.

### 16.13 사용자 폰트 추가

`%APPDATA%/lightnote/fonts/` 폴더에 `.ttf`/`.otf`/`.woff`/`.woff2` 파일을
넣고 앱을 다시 켜면 에디터 폰트 목록에 자동으로 나타난다. 폰트 이름은
파일명에서 따온다. 설정 화면의 `폰트 폴더 열기` 버튼으로 그 폴더를 바로
열 수 있다. (인터넷에서 폰트를 내려받지 않는다 — 사용자가 직접 넣은
파일만 읽는다.)

### 16.14 내보내기 · 가져오기 (집 PC ↔ 회사 PC)

- 트리에서 **페이지 / 섹션 / 노트북** 우클릭 → `📤 내보내기` 로 그 하위
  전체를 하나의 `.json` 번들 파일로 저장한다. 페이지 내용, 업무 속성,
  하위 계층이 모두 들어간다.
- 트리 상단 `📥` 버튼으로 번들을 가져오면 **항상 새 노트북**으로 만들어
  들여온다(id를 새로 발급). 기존 노트를 덮어쓰는 사고가 구조적으로
  일어나지 않는다.
- 가져오기 시 **PC 밖으로 나가면 의미가 없거나 위험한 참조는 제거**된다:
  캘린더 링크(`calendarLink`)와 액션별 태스크 id, 다른 페이지를 가리키는
  링크(`relatedPages`)와 페이지 종류의 문서 링크. 첨부 파일은 번들에
  포함되지 않으므로 필요하면 따로 옮겨야 한다.

## 17. LightNote — 업무 객체(업무 관리) 기능

일반 텍스트 노트만으로는 부족한 "이 노트는 진행 중인 업무다"라는 맥락을
페이지에 구조화된 필드로 얹는 기능. **완전히 AI-free** — 이 기능의 어떤
경로도 AI API를 호출하지 않는다(회사 환경 보안 제약에 따른 설계 원칙).

### 17.1 업무 속성 패널

페이지를 열면 에디터 위에 뜨는 패널(`WorkObjectPanel.tsx`). "＋ 업무 속성
추가"를 눌러야 활성화되며(강제 아님), 숨기면 데이터는 보존된 채 패널만
사라진다.

| 필드 | 설명 |
|---|---|
| 상태 | 예정 / 진행중 / 대기 / 완료 / 보류 |
| 우선순위 | 상 / 중 / 하 |
| 기한 · 시작 | 날짜 선택. 기한 기준 **D-day 배지**(D-3, D-DAY, ⚠지연 D+n)가 자동 표시 |
| 완료일 | 상태를 완료로 바꾸면 자동 기록, 되돌려도 유지(수동 삭제 가능) |
| 관련 부서/담당 | 자유 텍스트 |
| 관련 문서 | **클릭 가능한 링크 칩** — 🔗 외부 URL/파일 경로(정규화 후 `shell.openExternal`로 열림) 또는 📄 다른 LightNote 페이지(검색해서 연결, 클릭 시 해당 노트로 이동) |
| 다음 Action | 체크리스트. 각 항목마다 **개별 목표 일정**(날짜) 지정 가능, 체크 시 취소선+완료일 표시 |
| 결정사항(이력) | 최신순 텍스트 로그, 편집/삭제 가능 |

완료 처리 시 "Archives로 이동할까요?"를 물어 PARA 방식의 Archives
노트북으로 페이지를 옮겨주는 옵션 제공(강제 아님).

### 17.2 업무 현황 대시보드

상단 "📋 업무 현황" 버튼으로 여는 전용 오버레이 뷰(실제 페이지가 아님).
**업무** 모드와 **액션** 모드 두 가지로 전환 가능.

**업무 모드** — 페이지(업무) 단위 한 줄씩:
- 요약 카드: 진행중 / 오늘 마감 / 지연 / 이번주 완료
- 필터: 전체/진행중/예정/대기/지연/완료
- 표: 제목(+위치) · 상태 · 우선순위 · 기한 · D-day · 진행률(막대+분수) ·
  남은 액션 수 · 최근수정 — 모든 열 정렬 가능, 행 클릭 시 해당 노트로 이동
- 각 행 앞 **체크박스**로 업무를 골라 `보고서 내보내기`(§17.4) 가능

**액션 모드** — 모든 업무의 액션 항목을 한 줄씩 펼쳐서(스프레드시트형):
- 요약 카드: 전체 액션 / 미완료 / 지연 / 이번주
- 표: **분류**(노트북/섹션 이름) · **업무 내용**(액션 텍스트) · **목표
  일정** · **완료 여부**(클릭으로 토글, 연결된 캘린더 태스크도 함께
  완료 처리) · **주차**(ISO 주차, 예: W32) — 엑셀로 관리하던 업무
  체크리스트를 앱 안에서 그대로 재현한 뷰.

### 17.3 캘린더 연동 (현재 비활성화)

업무/액션을 플래너의 태스크로 등록하는 기능(Calendar A/B/C: 노트 단위
등록, 액션 단위 등록, 완료 상태 양방향 동기화)이 구현되어 있으나,
**현재 UI에서 숨김 처리**되어 있다 — 일정은 사내 Outlook으로 별도 관리하기
때문에 중복을 피하기 위함. `WorkObjectPanel.tsx`의
`CALENDAR_SYNC_ENABLED` 플래그 하나로 켜고 끌 수 있으며, 데이터 모델·IPC
브릿지는 그대로 남아 있어 언제든 재활성화 가능하다.

### 17.4 업무 진행 현황 보고서 내보내기

업무 현황 화면에서 체크박스로 업무를 고르고 `보고서 내보내기`를 누르면,
고른 업무들을 하나의 **Markdown 파일**로 저장한다.

설계 원칙은 **"업무 속성 = 정제된 내용, 페이지 내용 = 메모"** 다.
보고서에는 업무 속성에 적어 둔 정제된 내용만 나가고, 페이지 본문에
적어 둔 메모·초안은 **절대 나가지 않는다**. 그래서 페이지에는 마음껏
날것으로 적어 두고, 남에게 보여줄 문장만 속성에 정리하면 된다.

출력 항목과 서식(개조식 — `1.` / `a.` / `-`, `#` 헤더를 쓰지 않는다):

```
1. 결제 API 연동
   a. 목표 기한: 2026-09-30
   b. 업무 배경
      - 기존 PG사 계약 종료로 신규 연동 필요
   c. 업무 목적
      - 결제 실패율 3% 이하로 개선
   d. 진행 현황
      - 플로우 확정 (8/16)
      - 개발 환경 연동 테스트 완료 (8/28)
   e. Action Item
      - 에러 응답 케이스 정의 (~08/24)
      - 운영 배포 계획 수립 (~09/05)
   f. 의사결정 필요 사항
      - 결제 실패 시 재시도 정책(자동 3회 vs 수동)
```

- **날짜 표기**: 내용이 앞, 날짜가 뒤. 진행 현황은 `(8/16)`, Action Item은
  기한이므로 `(~08/24)`. 연도는 표기하지 않는다.
- **Action Item은 미완료 항목만** 나가고, 기한이 이른 순으로 정렬된다.
- **비어 있는 항목은 통째로 생략**되고, 남은 항목에 맞춰 `a. b. c.`가
  다시 매겨진다 — 빈 칸이 있는 보고서가 나오지 않는다.
- 상태·우선순위는 보고서에 넣지 않는다(목표 기한만 표기).
- 진행 현황·결정 사항의 **날짜**, Action Item·의사결정 필요 사항의
  **내용**은 업무 패널에서 직접 수정할 수 있다(입력 시 오늘 날짜가 자동
  채워지고, 필요하면 고치면 된다).

> 이 기능은 **AI를 전혀 호출하지 않는다.** 저장해 둔 필드를 규칙대로
> 조립할 뿐이라, API 키가 없는 회사 PC에서도 동일하게 동작한다.

## 18. 트레이 메뉴 · 딥링크

**시스템 트레이**(좌클릭 시 사이드바 표시, 우클릭 메뉴):
- "Daily Sidebar Planner" — 비활성 타이틀 행
- ─────────
- **Show Sidebar** — 사이드바 즉시 표시
- **Open Dashboard** — 대시보드 창 열기
- ─────────
- **Launch at Startup** — 체크박스, Windows 로그인 시 자동 실행 여부를
  즉시 반영/토글
- ─────────
- **Quit** — 앱 종료

앱은 모든 창이 닫혀도 트레이에 상주하며 종료되지 않는다 — 사이드바를
실수로 닫아도 트레이를 통해 언제든 복귀 가능하다.

**딥링크(`lightnote://` 커스텀 프로토콜)**: 각 LightNote 페이지에
`lightnote://page/<pageId>` 형태의 고유 링크가 있어, 탐색기·워드 등
외부에 붙여넣은 링크를 클릭하면 앱이 실행되며(꺼져 있었다면 콜드
스타트, 실행 중이었다면 기존 인스턴스에 전달) 해당 노트가 바로 열린다.
페이지 안의 "링크 복사" 기능으로 이 URL을 만들어 클립보드에 담을 수
있다.

## 19. 데이터 저장 구조

모두 로컬 파일 기반(외부 서버 없음, DB 엔진 없이 JSON 원자적 쓰기).

### 19.1 플래너 데이터

```
%APPDATA%/daily-sidebar-planner/
├── planner.json          # events, tasks, focusAreas, habits (+ 미사용 notes) — 단일 파일
└── window-settings.json  # 사이드바 위치/크기/업무시간/리마인더 설정
```

- `planner.json`은 메모리 캐시 후 변경 시마다 **원자적 쓰기**(임시
  파일에 쓰고 rename)로 저장되어, 저장 도중 강제 종료돼도 파일이
  깨지지 않는다. 손상된 파일은 `planner.json.corrupt-<timestamp>.bak`로
  백업하고 새로 시작한다.
- `window-settings.json`은 단순 동기 읽기/쓰기(원자적 쓰기 보호는 없음).
- `notes` 배열은 스키마상 존재하지만(레거시 노트 시스템, §15) 현재 UI
  경로에서 전혀 쓰이지 않는다.

### 19.2 LightNote 데이터

```
%APPDATA%/lightnote/lightnote-data/
├── notebooks.json        # 노트북 목록
├── <notebookId>/sections.json  # 해당 노트북의 섹션(플랫, parentId로 계층)
├── pages.json             # 페이지 인덱스
├── pages/<pageId>.json    # 페이지 실제 내용 {id, title, delta, updatedAt}
├── page-refs.json         # 페이지 간 링크(RELATED PAGES)
├── settings.json           # 테마/폰트/API 키 등
├── work-objects.json      # 페이지별 업무 객체 {pageId: WorkObject}
├── versions/<pageId>/     # 페이지 버전 스냅샷(페이지당 최근 30개)
├── attachments/<pageId>/  # 첨부 파일 원본 복사본
└── templates/<id>.json    # 페이지 템플릿 {id, name, delta, at}

%APPDATA%/lightnote/fonts/  # 사용자가 직접 넣는 폰트(.ttf/.otf/.woff/.woff2)
```

페이지는 UUID로 식별되므로 이동·이름변경과 무관하게 `work-objects.json`,
`page-refs.json`의 참조가 깨지지 않는다.

### 19.3 테스트 격리

`DSP_TEST_DATA_DIR` 환경 변수가 설정되면 위 두 데이터 루트가 모두 임시
디렉터리로 리다이렉트된다 — 자동화 테스트가 실제 사용자 데이터를
절대 건드리지 않도록 하는 안전장치.

## 20. 보안/프라이버시 원칙

- **AI는 항상 opt-in, 명시적 게이트**: 별도의 "AI 켜기/끄기" 스위치는
  없고, **Gemini API 키가 저장되어 있는지 여부**가 곧 AI 기능
  on/off다(LightNote의 질문/검색·AI Organize·일정 추출, 그리고
  §15의 이벤트/태스크 "✨ Brief" 모두 동일). 회사 PC처럼 키가 없는
  환경에서는 AI 관련 UI가 아예 나타나지 않는다.
- **업무 객체 기능은 100% AI-free**로 설계·구현되었다(어떤 코드
  경로도 AI API를 호출하지 않음) — 회사 환경 보안 요구사항에 따른
  명시적 제약.
- 모든 데이터는 로컬 파일 시스템에만 저장되며, 외부로 자동 전송되지
  않는다(단, AI 질문/요약 시 그 내용은 사용자가 등록한 API 키를
  통해 Google Gemini로 전송됨 — API 키가 없으면 이 경로 자체가
  비활성).
