# LightNote / 업무 객체 — 손으로 해보는 테스트 시나리오

> 대상: 이번 사이클에 추가된 기능 전체
> 목적: **자동 테스트가 통과했는데도 실제로 쓰면 이상한 것**을 잡아내기
> 소요: 전체 40~60분 / 섹션별로 끊어서 해도 됨

---

## 0. 이 문서를 읽는 법

각 기능마다 네 가지를 적었다.

| 항목 | 뜻 |
|---|---|
| **왜 해봐야 하나** | 이 기능이 어디서 깨질 만한가 — 근거 없는 불안이 아니라, 실제로 이런 유형이 터졌다 |
| **자동으로 이미 막아둔 것** | `scripts/verify-*.mjs`가 매번 확인하는 것. 여기 있는 건 손으로 다시 볼 필요 없다 |
| **사람만 볼 수 있는 것** | 자동 테스트가 원리적으로 못 잡는 것 — 이게 이 문서의 존재 이유 |
| **시나리오** | 순서대로 해보고, 합격 기준과 다르면 적어둘 것 |

### 자동 테스트가 원리적으로 못 잡는 것 4가지

자동 테스트는 "값이 맞는가"를 본다. 아래는 값이 맞아도 틀릴 수 있다.

1. **읽히는가** — 색이 `#f1f4f8`으로 정확히 들어갔어도, 그 위 글자가 안 보일 수 있다.
   (실제로 표 프리셋이 이랬다. 값은 전부 통과했는데 캡처를 보니 글자가 안 보였다.)
2. **손에 맞는가** — 버튼이 존재하고 눌리는 것과, 누르고 싶을 때 거기 있는 것은 다르다.
3. **내 진짜 데이터에서도 그런가** — 테스트는 항상 깨끗한 새 데이터로 시작한다.
   내 노트는 몇 달 된 데이터다. (실제로 "보고용 정리" 흰 화면이 이 차이에서 나왔다.)
4. **다른 PC에서도 그런가** — 회사 PC는 AI 키가 없고, 폰트가 다르고, 화면이 다르다.

### 전체를 관통하는 5가지 관점(렌즈)

어느 기능을 보든 이 다섯 개를 얹어서 보면 된다.

| 렌즈 | 질문 |
|---|---|
| 👁 **가독성** | 다크 테마에서도 읽히나? 라이트 테마로 바꿔도 깨지지 않나? |
| 🗄 **기존 데이터** | 새로 만든 페이지 말고, **예전부터 쓰던 페이지**에서도 되나? |
| 🔌 **껐다 켜기** | 앱을 완전히 종료했다 켜도 그대로 남아 있나? |
| 💼 **회사 PC** | AI 키 없이, 인터넷 없이, 내 폰트 없이도 되나? |
| ↩️ **되돌리기** | 잘못 눌렀을 때 `Ctrl+Z`나 다른 방법으로 복구되나? |

### 시작 전 준비

1. 앱을 켠다. LightNote 창을 연다.
2. **테스트용 노트북**을 하나 만든다 (예: `_테스트`). 실제 업무 노트에서 실험하지 말 것.
3. 단, 🗄 렌즈가 붙은 항목은 **일부러 예전 페이지에서** 해봐야 한다.
4. 문제를 발견하면 무엇을 눌렀고 무엇을 기대했는지 한 줄로 적어둘 것.

> **데이터 위치**: `%APPDATA%/lightnote/lightnote-data/`
> 크게 실험하기 전에 이 폴더를 통째로 복사해두면 언제든 되돌릴 수 있다.

## 1. 표 — 여러 셀 한꺼번에 서식

**왜 해봐야 하나**
Quill은 표 안에서 여러 셀을 드래그해도 "선택 범위"를 정상적으로 넘겨주지 않는다.
그래서 평범하게 만들면 **드래그를 시작한 셀 하나만** 바뀌고 나머지는 조용히 무시된다.
조용히 무시되는 게 핵심이다 — 에러가 안 뜨니까 사용자는 "왜 안 먹지?" 하고 몇 번 더 누른다.

**자동으로 이미 막아둔 것** (`verify-table-multi-format` 6/6)
드래그로 선택한 셀 전체에 글자 크기와 정렬이 들어가는지.

**사람만 볼 수 있는 것**
불규칙한 표 — 병합된 셀, 행마다 열 수가 다른 표, 표 안에 목록이 있는 셀.

**시나리오**
1. 4행 4열 표를 만든다.
2. 가운데 2×2 영역을 드래그로 선택 → 글자 크기를 `20`으로.
   - ✅ 네 칸 **모두** 커진다.
3. 같은 영역에서 **가운데 정렬**.
   - ✅ 표 전체가 아니라 **그 네 칸의 글자만** 가운데로 간다.
4. 셀 두 개를 우클릭 → 병합한 뒤, 병합된 셀을 포함해 드래그 선택 → 크기 변경.
   - ✅ 병합 셀도 같이 바뀐다. ❌ 아무 일도 안 일어나면 기록.
5. 한 셀 안에 글머리 목록을 넣고, 그 셀을 포함해 드래그 선택 → 크기 변경.
   - ✅ 목록 글자도 같이 바뀐다.

## 2. 표 스타일 프리셋

**왜 해봐야 하나**
이 기능은 **한 번 실패했던 자리**다. 처음엔 배경색만 칠했는데, 다크 테마에서는
글자가 원래 밝은 색이라 밝은 배경 위에 밝은 글자가 남아 거의 안 보였다.
자동 테스트는 "배경색이 `#f1f4f8`이다"를 확인하고 전부 통과했다. 캡처를 보고서야 알았다.
지금은 배경과 글자색을 항상 같이 바꾸도록 고쳤지만, **읽히는지는 여전히 눈으로만 확인된다.**

**자동으로 이미 막아둔 것** (`verify-table-preset-convert` 22/22)
머리행/본문/줄무늬 배경색이 서로 다른지, 글자색이 어둡게 들어갔는지,
`지우기`가 배경·글자색·굵게를 모두 되돌리는지.

**사람만 볼 수 있는 것**
- 👁 실제로 읽히는가, 그리고 **보기 좋은가**.
- 프리셋을 건 표를 Word나 메일에 붙였을 때 그 모습이 유지되는가.

**시나리오**
1. 5행 5열 표를 만들고 내용을 채운다.
2. 표 안에 커서를 두고 툴바 `표 스타일` → **머리행 강조**.
   - ✅ 첫 행만 파란 배경 + 굵게. 본문은 흰 배경.
   - 👁 글자가 또렷하게 읽히는가? 흐릿하면 실패다.
3. → **머리행 + 줄무늬**.
   - ✅ 짝수 본문 행에 옅은 회색. 표가 한눈에 행 구분이 되는가.
4. **설정에서 테마를 라이트로 바꾼다.** 표를 다시 본다.
   - 👁 라이트 테마에서도 이상하지 않은가? (밝은 표라 원래 잘 맞아야 한다)
   - 다크로 되돌린다.
5. → **스타일 지우기**.
   - ✅ 표가 테마 기본 모습으로 **완전히** 돌아온다. 굵게도 풀린다.
   - ❌ 흰 배경이 남거나 글자가 검은색으로 남으면 실패.
6. 표를 복사해서 **Word나 아웃룩 메일 본문에 붙여넣기**.
   - 💼 색과 굵게가 따라가는가? (여기가 실제 사용 목적이다)
7. 표 밖(본문)에 커서를 두고 `표 스타일`을 눌러본다.
   - ✅ 아무 일도 안 일어나거나 안내가 뜬다. 다른 곳이 망가지면 안 된다.

## 3. 텍스트 → 표 / 표 → 텍스트

**왜 해봐야 하나**
이건 **원본을 지우고 새로 만드는** 동작이다. 중간에 실패하면 내용이 사라진다.
가장 위험한 기능이라 되돌리기 확인이 특히 중요하다.
또 "탭이 있으면 탭, 없으면 쉼표"라는 규칙이 실제 내 데이터와 맞는지는 해봐야 안다 —
업무 내용에 쉼표가 들어 있으면 엉뚱한 곳에서 열이 갈린다.

**자동으로 이미 막아둔 것**
3행 3열 변환, 셀 순서, 원본 줄이 남지 않음, 왕복 후 빈 줄이 끼지 않음, 표 밖에서 누르면 안내.

**사람만 볼 수 있는 것**
- ↩️ **`Ctrl+Z`로 되돌아가는가** (자동 테스트 미검증 — 반드시 확인)
- 내 실제 엑셀 데이터가 제대로 갈리는가
- 셀 안에 쉼표가 있을 때 어떻게 되는가

**시나리오**
1. **엑셀에서 실제 업무 표를 복사**해서 페이지에 붙여넣는다.
2. 붙인 부분만 드래그로 선택 → 툴바 `→▦`(텍스트 → 표).
   - ✅ 열이 엑셀과 똑같이 갈린다.
   - ❌ 한 칸에 다 들어가면 탭이 아니라 다른 문자로 붙은 것이다. 기록.
3. **즉시 `Ctrl+Z`를 누른다.**
   - ↩️ 원래 텍스트로 돌아오는가? **안 돌아오면 이건 심각한 문제다 — 반드시 기록.**
   - (돌아왔으면 `Ctrl+Y`나 다시 변환해서 진행)
4. 쉼표가 들어간 문장으로 시험한다. 탭 없이 이렇게 3줄:
   ```
   기획, 플로우 확정
   개발, 에러 케이스 정의, 08/24
   QA, 검증
   ```
   - ✅ 열 수가 제각각인 줄도 표로 들어간다 (모자란 칸은 빈 칸).
   - 👁 이 규칙이 내 사용 방식과 맞나? 안 맞으면 "쉼표 말고 탭만" 같은 요구로 적어둘 것.
5. 표 안에 커서를 두고 `▦←`(표 → 텍스트).
   - ✅ 표가 사라지고 탭 구분 줄로 돌아온다. 앞에 빈 줄이 끼지 않는다.
6. 다시 `→▦`로 표를 만든다. **왕복해도 내용이 같은가?**
   - ✅ 셀 내용 손실 없음.
   - ⚠️ 알려진 한계: 왕복하면 **표에 걸었던 스타일과 병합은 사라진다** (텍스트에는 그 정보가 없다). 이건 정상.
7. 아주 큰 표로 한계를 확인한다 — 120줄짜리 텍스트를 선택하고 변환.
   - ✅ "표가 너무 큽니다 (최대 100행 × 30열)" 안내가 뜨고, **원본 텍스트는 그대로 남아 있다.**
   - ❌ 텍스트가 지워졌는데 표도 안 생기면 최악이다. 반드시 확인.

## 4. 붙여넣기 글자 크기 정규화 · 사용자 폰트

**왜 해봐야 하나**
Word와 웹은 글자 크기를 `pt`로, LightNote는 `px`로 쓴다. 그대로 붙으면
"11pt"가 "11px"로 들어와 갑자기 작아진다. 이걸 변환해서 넣는데, **모든 출처가
같은 방식으로 크기를 쓰지 않는다** — 사내 위키, 아웃룩, PDF 뷰어가 다 다르다.
그래서 실제로 내가 자주 복사해오는 곳에서 해봐야 한다.

**자동으로 이미 막아둔 것** (`verify-paste-size-normalize` 5/5, `verify-custom-fonts` 10/10)
pt 표기가 px로 환산되어 들어오는지, 폰트 폴더 스캔·확장자 인식·이름 추출.

**사람만 볼 수 있는 것**
💼 **내가 실제로 복사해오는 출처**에서의 결과. 그리고 폰트가 실제로 예쁘게 렌더되는가.

**시나리오**
1. 자주 쓰는 출처 3곳에서 각각 복사해 붙여넣는다 — 사내 위키 / 아웃룩 메일 / Word 문서.
   - ✅ 주변 본문과 글자 크기가 비슷하게 들어온다.
   - ❌ 유독 크거나 작으면 **어느 출처인지 적어둘 것** (출처별로 규칙이 다르다).
2. 표를 통째로 복사해 붙여넣는다.
   - ✅ 표 구조와 글자 크기가 같이 유지된다.
3. **폰트**: `%APPDATA%/lightnote/fonts/` 폴더에 `.ttf` 파일을 하나 넣는다.
   (설정 → `📁 폰트 폴더 열기` 로 바로 열 수 있다.)
4. **앱을 완전히 종료했다가 다시 켠다.** (재시작해야 반영된다)
5. 설정 → 에디터 폰트 목록.
   - ✅ 넣은 폰트가 파일명에서 딴 이름으로 보인다.
   - 골라서 적용 → 👁 한글이 깨지지 않고 잘 나오는가?
6. 💼 **회사 PC 관점**: 그 폰트가 없는 PC에서 이 페이지를 열면?
   - ✅ 기본 폰트로 대체되어 읽을 수는 있어야 한다. 글자가 사라지면 안 된다.

## 5. 위/아래 첨자 · 서식 복사 · 한글 다단계 번호

**왜 해봐야 하나**
**서식 복사**는 "버튼을 누른 뒤 다음 선택에 적용"이라는 2단계 동작이라, 중간에
포커스가 튀면 조용히 풀린다. 실제로 버튼이 편집기 포커스를 뺏는 버그가 있었다.
**한글 다단계 번호**는 `1. → 가. → 1) → 가)` 자동 전환이라, 들여쓰기를 오르내릴 때
번호가 어긋나기 쉽다.

**자동으로 이미 막아둔 것** (`verify-editor-basics2` 11/11)
첨자 적용, 서식 복사 집기/붙이기/해제, 들여쓰기 단계별 번호 형식.

**사람만 볼 수 있는 것**
↩️ 실제 문서를 쓰는 흐름에서 자연스러운가 — 특히 서식 복사를 연속으로 쓸 때.

**시나리오**
1. `H2O`를 쓰고 `2`만 선택 → 아래 첨자. `m2` → 위 첨자.
   - ✅ 줄 간격이 이상해지지 않는다.
2. **서식 복사**: 빨간색 굵은 글자를 선택 → `🖌` 클릭 → 다른 문장을 드래그.
   - ✅ 그 문장이 빨간 굵은 글씨가 되고, 붓이 자동으로 꺼진다.
3. 붓을 켠 상태에서 **아무것도 안 하고 다른 곳을 클릭**한다.
   - ✅ 붓이 켜진 채로 남아 있고, 다음 드래그에 적용된다. (또는 명확히 꺼진다)
   - ❌ 켜진 것처럼 보이는데 적용이 안 되면 기록.
4. 붓을 켠 뒤 **한 번 더 눌러** 취소한다. → ✅ 하이라이트가 꺼진다.
5. **번호 목록**: `1.` 목록을 만들고 `Tab`으로 들여쓰기를 3단계까지 내려간다.
   - ✅ `1.` → `가.` → `1)` → `가)` 순으로 바뀐다.
6. 3단계에서 `Shift+Tab`으로 다시 올라온다.
   - ✅ 번호가 원래 형식으로 되돌아오고, **번호가 이어진다** (1로 리셋되지 않는다).
7. 이 목록을 Word에 붙여넣는다. → 💼 번호 모양이 유지되는가?

## 6. 찾기 · 바꾸기 (`Ctrl+F` / `Ctrl+H`)

**왜 해봐야 하나**
"모두 바꾸기"는 되돌리기 어려운 동작이다. 그리고 바꾸는 도중 문서가 변하면
위치 계산이 어긋나 **엉뚱한 곳을 바꾸거나 하나를 건너뛴다**. 실제로 이 위치
계산 때문에 한 번 고쳤다.

**자동으로 이미 막아둔 것** (`verify-find-replace` 9/9)
일치 개수, 다음/이전 이동, 하나 바꾸기, 모두 바꾸기.

**사람만 볼 수 있는 것**
표 안·목록 안·첨부 링크 안의 글자도 잡히는가. 그리고 ↩️ 모두 바꾸기 되돌리기.

**시나리오**
1. 같은 단어가 표 안, 목록 안, 본문에 각각 들어간 페이지를 만든다.
2. `Ctrl+F` → 그 단어 입력.
   - ✅ 개수가 실제와 맞는가? **표 안의 것도 세는가?**
3. `Enter`를 반복해 끝까지 → ✅ 마지막에서 처음으로 돌아온다.
4. `Ctrl+H`로 바꾸기 칸에 다른 단어 → **하나만 바꾸기**.
   - ✅ 현재 위치 하나만 바뀌고, 다음으로 이동한다.
5. **모두 바꾸기**.
   - ✅ 표 안과 목록 안까지 전부 바뀐다.
6. **`Ctrl+Z`를 눌러본다.**
   - ↩️ 한 번에 전부 되돌아오는가, 하나씩 되돌아오는가? 어느 쪽인지 기록.
   - (되돌리기가 안 되면 §7 버전 기록이 안전망이다 — 그것도 확인)
7. 대소문자가 섞인 영문 단어로 반복. → 👁 내 기대와 맞나?

## 7. 버전 기록 (`🕘 버전`)

**왜 해봐야 하나**
이건 **다른 기능이 사고를 쳤을 때의 안전망**이다. 안전망은 필요한 순간에
비어 있으면 아무 의미가 없다. 그런데 이 기능에는 **일부러 넣은 제약 2개**가 있다:
- 3분에 한 번만 저장 (저장할 때마다 남기면 금방 쓰레기가 된다)
- 페이지당 30개까지

그래서 **"방금 고쳤는데 버전이 안 생겼다"가 정상 동작**이다. 이걸 모르면 버그로 오해한다.
거꾸로, 진짜로 필요한 순간에 버전이 있는지는 확인해둬야 한다.

**자동으로 이미 막아둔 것** (`verify-page-versions` 13/13)
스냅샷 생성, 3분 미만 재저장 시 건너뜀, 내용 동일 시 건너뜀, 30개 초과분 삭제, 되돌리기.

**사람만 볼 수 있는 것**
🔌 **며칠에 걸친 실제 사용**에서 버전이 쌓이는 모습. 미리보기로 어느 시점인지 알아볼 수 있는가.

**시나리오**
1. 페이지를 열고 크게 고친다 → 잠깐 기다린다(자동 저장).
2. `🕘 버전` 클릭. → ✅ 목록이 뜬다. 시각이 알아볼 수 있게 표시되는가?
3. **바로 다시 고치고** 버전 목록을 연다.
   - ✅ 새 버전이 **안 생기는 게 정상**이다 (3분 제한). 이걸 알고 있으면 된다.
4. 3분 이상 지난 뒤 다시 고치고 확인. → ✅ 이번엔 새 버전이 생긴다.
5. 목록에서 이전 버전을 눌러 **미리보기**.
   - 👁 내용이 충분히 보여서 "이 시점이 맞다"고 판단할 수 있는가?
6. **되돌리기** 실행.
   - ✅ 그 시점 내용으로 돌아온다.
   - ✅ **되돌리기 직전 상태도 새 버전으로 남아 있다** → 되돌리기 자체를 취소할 수 있다.
7. 🗄 **오래된 페이지**에서 `🕘 버전`을 열어본다.
   - ✅ 버전이 없으면 "없음"이 뜬다. 흰 화면이나 에러면 실패.
8. 며칠 뒤 다시 와서 → 🔌 버전이 자연스럽게 쌓여 있는가?

## 8. 파일 첨부

**왜 해봐야 하나**
첨부는 **원본 파일을 복사해서 앱 폴더에 넣는다.** 그래서 원본을 지워도 살아 있다 —
이게 이 설계의 핵심 이점인데, 진짜 그런지는 원본을 지워봐야 안다.
반대로 **한계**도 있다: 내보내기 번들에는 첨부가 안 들어간다. 회사 PC로 옮길 때
첨부가 사라지는 걸 미리 알아둬야 한다.

**자동으로 이미 막아둔 것** (`verify-attachments` 9/9)
파일 복사, 링크 삽입, 경로 탈출 차단, 페이지 영구 삭제 시 첨부 정리.

**사람만 볼 수 있는 것**
💼 실제 파일(한글 이름, 공백, 큰 엑셀)이 진짜로 열리는가.

**시나리오**
1. `📎`로 **한글 이름에 공백이 있는 엑셀 파일**을 첨부한다.
   - ✅ 본문에 `📎 파일명` 링크가 생긴다.
2. 링크를 클릭. → ✅ 엑셀이 뜬다. ❌ 안 열리면 파일명을 적어둘 것.
3. **원본 파일을 다른 곳으로 옮기거나 지운다.** 다시 링크 클릭.
   - ✅ **그래도 열린다** (복사본이 앱 폴더에 있으므로). 이게 핵심 확인 지점이다.
4. PDF, 이미지, 20MB 이상 큰 파일로 반복.
   - 👁 큰 파일 첨부 시 앱이 잠깐 멈추는가? 얼마나?
5. ⚠️ **알려진 한계 확인**: 이 페이지를 §11 방식으로 내보내고 다른 곳에 가져온다.
   - ✅ 링크는 남아 있지만 **파일은 따라가지 않는다**. 이건 정상 — 첨부는 따로 옮겨야 한다.
   - 👁 이 동작이 받아들일 만한가? 아니면 "번들에 첨부도 포함" 요구로 적어둘 것.

## 9. PDF 내보내기 (`🖨 PDF`)

**왜 해봐야 하나**
화면과 인쇄물은 다르다. 특히 **다크 테마 그대로 PDF가 나오면 종이가 새까맣게 된다.**
표가 페이지 경계에서 잘리는 것도 화면에서는 절대 안 보인다.

**자동으로 이미 막아둔 것** (`verify-pdf-export` 5/5)
저장 대화상자 호출과 파일 생성.

**사람만 볼 수 있는 것**
👁 **PDF를 실제로 열어서 보는 것.** 이건 전적으로 사람 몫이다.

**시나리오**
1. 표 + 이미지 + 색 있는 글자 + 첨부 링크가 모두 있는 긴 페이지(2페이지 이상)를 만든다.
2. `🖨 PDF` → 저장 → **PDF를 연다.**
3. 확인할 것:
   - 👁 배경이 흰색인가? (다크 테마인데 검은 배경으로 나오면 실패)
   - 👁 표가 페이지 경계에서 어떻게 잘리는가?
   - 👁 이미지가 잘리거나 빠지지 않았나?
   - 👁 §2에서 건 표 프리셋 색이 유지되나?
4. **라이트 테마로 바꾸고 다시 내보낸다.** → 두 PDF가 같은가, 다른가?
5. 그 PDF를 인쇄하거나 메일에 첨부해본다. → 💼 이대로 남에게 보낼 만한가?

## 10. 하위 페이지 · 페이지 템플릿

**왜 해봐야 하나**
하위 페이지는 트리에 **계층**을 만든다. 계층이 있으면 항상 따라오는 질문이 있다 —
**부모를 지우면 자식은?** 부모를 옮기면 자식은 따라가나? 이건 데이터가 꼬이기 쉬운 자리다.
템플릿은 "업무 페이지 뼈대를 재사용"이 목적이니, 그 목적대로 되는지가 핵심이다.

**자동으로 이미 막아둔 것** (`verify-subpage-template` 12/12)
parentId 저장, 3단계 들여쓰기(0/26px/40px), 부모>자식>손자 순서, 메뉴 항목,
템플릿 저장·목록·생성·삭제.

**사람만 볼 수 있는 것**
🗄 부모 삭제/이동 시 자식의 운명. 그리고 템플릿이 실제 업무 흐름에 맞는가.

**시나리오**
1. 페이지 우클릭 → `📑 하위 페이지 추가`를 2단계까지. → ✅ 트리에서 계단식으로 보인다.
2. **부모 페이지를 삭제한다.**
   - 자식은 어떻게 되는가? 같이 휴지통으로? 최상위로 올라오나? 사라지나?
   - 🗄 **어떤 동작이든 기록할 것.** 그리고 그게 내가 기대한 것인지 판단.
3. 휴지통에서 부모를 **복원**한다. → ✅ 계층이 복원되는가?
4. 부모 페이지를 **다른 섹션으로 드래그**한다. → 자식이 따라가는가?
5. **템플릿**: 업무 페이지 뼈대(배경/목적/진행 현황 항목)를 만들고
   우클릭 → `💾 템플릿으로 저장`.
6. 섹션 우클릭 → `📑 템플릿에서 페이지 추가` → 방금 만든 템플릿 선택.
   - ✅ 내용이 그대로인 새 페이지가 열리고, 제목이 템플릿 이름이다.
   - 👁 제목이 템플릿 이름인 게 편한가, 아니면 빈 제목이 나은가? 기록.
7. 그 새 페이지를 고친다. → ✅ **원본 템플릿은 안 바뀐다** (복사본이어야 한다).
8. 💼 실제 업무를 이 템플릿으로 하나 시작해본다. 뼈대가 실제로 쓸 만한가?

## 11. 내보내기 · 가져오기 (집 PC ↔ 회사 PC)

**왜 해봐야 하나**
이 기능의 **존재 이유가 두 PC를 오가는 것**이다. 그러니 한 PC 안에서 아무리
테스트해도 절반만 확인한 것이다. 그리고 가져오기는 설계상 **일부러 정보를 버린다** —
캘린더 링크, 태스크 id, 다른 페이지 링크. 옮긴 쪽에서 그게 없는 게 정상인데,
모르면 "데이터가 유실됐다"고 오해한다.

**자동으로 이미 막아둔 것** (`verify-export-import` 16/16)
페이지/섹션/노트북 번들 구조, 새 노트북으로만 들어옴, 위험한 참조 제거.

**사람만 볼 수 있는 것**
💼 **실제로 회사 PC에서 열리는가.** 이건 파일을 옮겨야만 확인된다.

**시나리오 (집 PC)**
1. 업무 속성이 붙은 페이지가 여러 개 든 섹션을 우클릭 → `📤 내보내기`.
   - ✅ `.json` 파일이 저장된다. 크기가 0이 아니다.
2. 노트북 단위로도 내보내본다.

**시나리오 (회사 PC — 파일을 USB/메일로 옮긴 뒤)**
3. 회사 PC에서 트리 상단 `📥` → 그 파일 선택.
   - ✅ **새 노트북**으로 들어온다. 기존 노트북이 덮어써지지 않는다 ← 가장 중요.
4. 가져온 페이지들을 확인:
   - ✅ 본문, 표, 업무 속성(배경/목적/진행 현황/Action Item)이 그대로 있다.
   - ✅ 하위 페이지 계층이 유지된다.
   - ⚠️ 첨부 파일은 없다 (정상, §8 참고).
   - ⚠️ 다른 페이지로 가는 링크가 없다 (정상 — 그 페이지가 이쪽에 없으니까).
5. 💼 **AI 키가 없는 상태에서** 가져온 페이지의 §12 보고서 내보내기를 해본다.
   - ✅ 정상 동작해야 한다. AI를 전혀 쓰지 않는 경로다.
6. 같은 파일을 **한 번 더 가져온다.**
   - ✅ 또 다른 새 노트북이 생긴다 (합쳐지지 않는다). 👁 이게 편한가? 기록.
7. 회사에서 이어서 작업한 뒤 다시 내보내 집으로 가져온다.
   - 👁 왕복이 실제로 쓸 만한 흐름인가? 매번 새 노트북이 생기는 게 감당되나?
   - **이 항목이 이 기능의 진짜 합격 기준이다.**

## 12. 업무 진행 현황 보고서 내보내기

**왜 해봐야 하나**
이 기능은 **남에게 보여줄 문서**를 만든다. 그래서 두 가지가 동시에 맞아야 한다.
1. **안 나가야 할 게 안 나가는가** — 페이지 본문의 날것 메모가 보고서에 새면
   그건 단순 버그가 아니라 사고다. (설계 원칙: 업무 속성 = 정제된 내용, 페이지 = 메모)
2. **서식이 사람이 쓴 것처럼 보이는가** — `#` 헤더를 쓰지 않고 개조식으로 바꾼 이유가 그것이다.

그리고 이 기능은 **다른 PC에서 흰 화면으로 죽은 적이 있다.** 예전에 만든 업무 페이지에는
새로 생긴 필드(배경/목적/진행 현황)가 아예 없어서 그렇다. 지금은 고쳤지만,
🗄 **오래된 페이지에서 열어보는 것**이 이 기능의 필수 확인 항목이다.

**자동으로 이미 막아둔 것** (`verify-report-export` 24/24, `verify-work-object-migration` 11/11)
항목 순서와 개조식 서식, 날짜 표기(`플로우 확정 (8/16)`, `에러 응답 케이스 정의 (~08/24)`),
미완료 Action만 출력, 기한순 정렬, 빈 항목 생략 후 a/b/c 재부여, 옛 데이터 자동 보정.

**사람만 볼 수 있는 것**
👁 **보고서를 실제로 읽어보고 "이대로 팀장에게 낼 수 있는가"** 판단하는 것.

**시나리오**
1. 🗄 **가장 오래된 업무 페이지**를 연다. 업무 패널 → `📋 보고용 정리`를 펼친다.
   - ✅ 흰 화면이나 에러 없이 열린다. **이 확인이 가장 중요하다.**
2. 진행 현황을 하나 추가한다. → ✅ 오늘 날짜가 자동으로 들어간다.
3. 그 **날짜를 과거로 고쳐본다.** → ✅ 수정된다.
4. Action Item 하나를 추가하고 **내용을 고친다**. 기한도 넣는다. → ✅ 둘 다 수정된다.
5. 페이지 **본문에는 정리 안 된 메모**를 잔뜩 써둔다 (예: "이거 확인 필요, 아직 모름").
6. 업무 현황 → 업무 모드 → 체크박스로 2~3개 선택 → `보고서 내보내기`.
7. **생성된 .md 파일을 연다.** 확인할 것:
   - ✅ 5번의 날것 메모가 **없다**. ← 있으면 심각한 문제.
   - ✅ 완료된 Action Item은 안 나온다.
   - ✅ 날짜가 `플로우 확정 (8/16)` 형식이다 (내용 먼저, 날짜 뒤, 연도 없음).
   - ✅ 비워둔 항목(예: 업무 배경을 안 썼으면)이 통째로 빠지고, a/b/c가 다시 매겨져 있다.
   - ✅ 상태·우선순위는 없고 목표 기한만 있다.
8. 👁 **소리 내어 읽어본다.** 이대로 주간 보고에 붙일 수 있는가?
   - 어색한 부분이 있으면 그 문장을 그대로 적어둘 것 — 서식 조정 요구가 된다.
9. 그 내용을 Word나 메일에 붙여넣는다. → 💼 개조식 들여쓰기가 유지되는가?
10. 💼 회사 PC(AI 키 없음)에서 6~7번을 반복. → ✅ 동일하게 동작해야 한다.

## 13. 업무 현황 대시보드 · 트리 📋 표시

**왜 해봐야 하나**
업무 현황은 **여러 노트북에 흩어진 데이터를 한 화면에 모으는** 뷰다.
데이터가 하나라도 이상하면(기한이 없거나, 액션이 0개거나, 페이지가 휴지통에 있거나)
집계가 틀어지거나 화면이 죽는다. 그리고 정렬·필터는 "그럴듯한 숫자"를 보여주기 때문에
**틀려도 눈치채기 어렵다** — 그래서 몇 개는 손으로 세어 대조해야 한다.

**자동으로 이미 막아둔 것** (`verify-work-list`, `verify-tree-work-icon` 5/5)
업무/액션 모드 전환, 정렬, ISO 주차 계산, 완료 토글, 트리 📋 아이콘.

**사람만 볼 수 있는 것**
👁 숫자가 **실제와 맞는가**. 그리고 액션 모드가 기존 엑셀을 대체할 만한가.

**시나리오**
1. 상단 `📋 업무 현황` → **업무 모드**.
   - ✅ 요약 카드(진행중/오늘 마감/지연/이번주 완료)의 숫자를 **손으로 세어 대조**한다.
   - ❌ 하나라도 다르면 어느 카드인지 기록.
2. 필터를 하나씩 눌러본다. → ✅ 합이 전체와 맞는가?
3. 각 열 머리를 눌러 정렬. → ✅ 기한 정렬 시 **기한이 없는 항목**은 어디로 가나? 기대와 맞나?
4. 행을 클릭. → ✅ 해당 노트로 이동한다.
5. **액션 모드**로 전환.
   - ✅ 분류/업무 내용/목표 일정/완료 여부/주차 — **원래 쓰던 엑셀과 같은 모양인가?**
   - 👁 이 화면이 엑셀을 대체할 수 있나? 부족한 열이 있으면 적어둘 것.
6. 완료 여부를 클릭해 토글. → ✅ 즉시 반영되고, 🔌 앱을 껐다 켜도 유지된다.
7. 주차(W33 등)를 이번 주 실제 주차와 대조. → ✅ 맞는가? (연말·연초에 특히 틀리기 쉽다)
8. 🗄 **업무 속성이 없는 일반 페이지**가 목록에 섞여 들어오지 않는지 확인.
9. 좌측 트리에서 → ✅ 업무 페이지에만 📋가 붙어 있다. 일반 메모와 구분되는가.
10. 업무 페이지를 **삭제(휴지통)**한 뒤 업무 현황을 연다.
    - ✅ 목록에서 빠진다. 숫자도 같이 줄어든다. 에러가 나면 기록.

## 14. 캘린더 UI 비활성화 확인

**왜 해봐야 하나**
캘린더 기능은 **지운 게 아니라 숨긴 것**이다 (`CALENDAR_SYNC_ENABLED = false`).
숨김이 불완전하면 어딘가에 버튼이 남아 있고, 그걸 누르면 Outlook과 중복된
일정이 생긴다. "안 보이면 된 것"이 아니라 **어디에도 안 보이는지**를 봐야 한다.

**시나리오**
1. 업무 패널을 위에서 아래까지 훑는다. → ✅ 캘린더/태스크 등록 버튼이 **하나도 없다.**
2. 액션 항목마다 확인. → ✅ 액션별 등록 버튼도 없다.
3. 업무 현황 두 모드 모두 확인. → ✅ 캘린더 관련 열·버튼이 없다.
4. 🗄 **예전에 캘린더에 등록해둔 업무 페이지**를 연다.
   - ✅ 에러 없이 열린다. 예전 링크 때문에 화면이 깨지지 않는다.
5. 플래너(대시보드) 쪽 태스크 목록을 본다.
   - 👁 예전에 등록된 태스크가 남아 있는가? 남아 있다면 정리할지 판단.

## 15. 마무리 — 전체를 한 번에 흔들어보기

개별 기능이 다 통과해도, 섞어 쓰면 깨지는 경우가 있다.

1. 한 페이지에 **표 + 프리셋 + 첨부 + 하위 페이지 + 업무 속성**을 전부 넣는다.
2. 그 페이지에서 찾기·바꾸기를 하고, PDF로 내보내고, 버전을 되돌려본다.
3. 그 섹션을 내보내고 → 가져오고 → 보고서를 뽑는다.
4. **앱을 완전히 종료하고 다시 켠다.** → 🔌 전부 그대로인가?
5. 테마를 라이트↔다크로 두 번 왕복한다. → 👁 깨지는 곳이 있나?

여기까지 문제가 없으면, 실제 업무에 올려도 된다.

## 문제를 발견했을 때

이 형식으로 적어주면 바로 재현해서 고칠 수 있다.

```
[기능] 표 스타일 프리셋
[무엇을 했나] 5행 표에 '머리행 + 줄무늬'를 걸고 라이트 테마로 전환
[기대] 표가 그대로 보인다
[실제] 머리행 글자가 배경에 묻혀 안 보인다
[재현] 매번 / 가끔 / 한 번만
```

**§10-2(부모 페이지 삭제 시 자식)**, **§12-1(오래된 업무 페이지 열기)** 는
아직 사람이 확인하지 않은 경로다. 이 넷은 꼭 해보길 권한다.
